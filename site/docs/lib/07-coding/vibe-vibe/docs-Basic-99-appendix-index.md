## 怎么用附录最值回票价

如果你现在已经在正文里推进项目，最推荐的方式不是“从 A 看到 G”，而是带着具体问题来查。

- 不知道怎么写需求，就先看 `A`
- 报错了，就先看 `B`
- 界面卡住了，就去翻 `C`
- 准备做较大改动，先看 `D`
- 接 API 或上线前，先看 `E`
- 判断项目边界时，去看 `F`
- 想继续系统补课时，去看 `G`

这样用，附录才真的会变成推进器，而不是额外负担。
