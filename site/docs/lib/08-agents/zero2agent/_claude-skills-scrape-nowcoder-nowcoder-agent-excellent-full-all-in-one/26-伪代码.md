16. Loop Engineering是什么？

这道题问的是Agent循环控制。

我的回答：

Loop Engineering指的是对Agent循环执行过程的精细化控制工程。

核心要素：

循环条件：什么时候继续、什么时候终止
步数限制：最大迭代次数
状态管理：每次迭代更新上下文
异常处理：工具超时、返回错误时的策略
观察裁剪：工具返回内容太长时如何截断

其实就是把Agent的循环从"while true"变成一个可控、可观测、可终止的工程系统。

17. Graph Engineering是什么？和Loop Engineering有什么区别？

这道题问的是两个工程概念的对比。

我的回答：

Graph Engineering：把Agent任务流程组织成有向图，节点是步骤（推理、工具调用、条件判断），边是流转路径。支持分支、并行、循环、合并。

Loop Engineering：关注的是单个Agent的循环迭代控制，强调的是"步数管理"和"状态维护"。

区别：

关注层级

任务流程编排

单次循环控制

结构

图（节点+边）

循环（推理→行动→观察）

适用

复杂多步骤任务

ReAct类Agent

粒度

粗（步骤级）

细（单次迭代级）

两者可以结合：Graph里每个节点可能内部就是一个Loop。

19. PDF/表格/条款类文档怎么解析和切分？

这道题和之前高德面过的PDF切分类似，但更聚焦在表格和条款上。

我的回答：

PDF解析：

文本型PDF：用PyPDF2或pdfplumber提取文本+坐标
扫描型PDF：用OCR识别

表格解析：

检测表格边界，提取行列结构，保留表头
对于复杂表格（合并单元格），用Camelot或Tabula

条款切分：

按条款编号层级切分（1.1、1.1.1）
每条条款保留完整上下文（上级条款的内容）
元数据记录：文档名、章节路径、版本号

切分原则：保持语义完整性 > 固定字数切分。

21. 多轮对话下怎么解决上下文断裂和幻觉？

我的回答：

上下文断裂：

每轮做Query改写，把指代和省略补全成完整问题
会话状态管理：记录当前对话的主题和关键实体

幻觉：

生成时强制引用检索结果
对时间、地点、数字等关键事实做后校验

两者的关系是：上下文断裂往往是幻觉的诱因，理解错了自然会答错。

22. 这个项目有哪些不足？和后面Agent项目比差在哪？

这道题是让做项目对比。

我的回答：

知识助手项目的不足：

只能回答，不能行动（只读不写）
无法处理需要跨文档推理的复杂问题
多轮对话能力弱

和Agent项目的差距：

Agent能调用工具，知识助手只能检索
Agent有记忆和规划能力，知识助手是Query-Response模式
结论：Agent是知识助手的超级版
23. 怎么平衡准确率和效率？混合检索/TOPN精排/控制上下文长度/模型路由？

这道题问的是系统级的权衡。

几个手段配合使用：

混合检索：BM25（快）+ 向量（准），RRF融合

TopN精排：粗排召回200条，精排只用前20条

控制上下文长度：

检索TopN固定（比如10条）
每条文档截断到500字
动态计算，超出预算就降低N或缩短截断

模型路由：

简单问题走小模型（快、便宜）
复杂问题走大模型（准）

def longest_common_substring(s1: str, s2: str) -> str:
    m, n = len(s1), len(s2)
    # dp[i][j] 表示 s1[:i] 和 s2[:j] 的最长公共子串长度
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    max_len = 0
    end_pos = 0
     
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
                if dp[i][j] > max_len:
                    max_len = dp[i][j]
                    end_pos = i
     
    return s1[end_pos - max_len: end_pos]
