## Q：上下文预算不足时，如何按任务依赖压缩，而不是按时间删除旧消息？

> 来源：腾讯互娱全栈开发（AI）二面（2026-08-13） / [字节 AI 应用开发二面](https://www.nowcoder.com/feed/main/detail/7e8a821479a649fd914e449d312eeb95)【[百度后端一面](https://www.nowcoder.com/discuss/924730985210458112)追问：上下文压缩时会对所有内容一视同仁，还是会侧重不同内容？；具体应该如何压缩上下文？】

**新手答**：“保留最近几轮，把更早内容做摘要。”

**高手答**：先把上下文拆成目标、硬约束、决策、证据、工具结果、副作用状态和待办，并建立当前计划对这些节点的依赖。优先保留高依赖、高可信、与未完成步骤相关的信息；已否决方案只留结论和原因，大工具结果转为带来源的结构化事实。系统规则、权限和已发生副作用不得由模型摘要。压缩后用执行日志校验“已完成/未完成”和关键约束是否一致。

对 Code Agent，依赖不能只由消息时间推断：应结合 AST/LSP 引用、构建图、测试覆盖和当前 diff 建图。与本次编辑直接相关的类型、接口、调用者和验收测试优先保留；已完成步骤仅保留 patch 和验证证据指针。若依赖图未知或索引已过期，应重新查询而不是自动压缩掉可能影响编译和行为的上下文。

**差距在哪**：新手按消息年龄压缩，高手按任务因果关系管理工作集。
