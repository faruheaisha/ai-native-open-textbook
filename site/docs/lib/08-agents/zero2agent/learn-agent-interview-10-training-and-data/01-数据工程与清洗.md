## 数据工程与清洗

### Q：构造数据集遇到过什么难点，怎么解决？

> 来源：腾讯AI应用开发【CVTE AI应用工程师一面追问：合成数据集质量达不到预期怎么办】【[字节 Seed 具身数据一面](https://www.nowcoder.com/feed/main/detail/657dfac8ca5c49f28492a1110b95f7cd)追问：标注一致性与自动质检】【[Momenta 大模型算法工程师一面](https://www.nowcoder.com/feed/main/detail/f7518c865e07491cb1518d288698813c)追问：长尾样本对齐】

**新手答**：“数据不够，就多标一些。”

**高手答**：

最大的问题不是数据不够，而是**数据不真实**。

人工构造的数据常常太标准——用户表达很整齐，参数给得很全，工具永远成功。结果上线之后用户一句话没说全，模型就不会了。

三个核心难点和解法：

**难点一：数据不真实**
→ 把真实线上 query 引进来，按意图、复杂度、缺参情况、歧义情况分桶，然后做针对性补齐

**难点二：标注不一致**
→ 同一种问题不同人可能给出不同工具路径，所以需要**先统一 schema 和决策标准**，再开始标注

不要只用一个总一致率掩盖问题。先按标签、任务阶段和难度切片，在一部分样本上做多人重叠标注；把“口径不清”“确有多解”“标注错误”分开，再用金标样本、仲裁记录和规则版本回写标注规范。Kappa 一类指标可以辅助观察，但类别极不均衡时必须同时看分标签混淆和原始分歧样本。

**难点三：长尾样本太少**
→ 靠模板改写、对抗生成和人工补充边界案例，把最容易出事故的地方优先补上

长尾治理要先定义业务切片，而不是把所有低频样本简单过采样。对每个 tail slice 记录覆盖率、错误成本和来源，结合真实失败、受约束合成和人工补标扩充；训练时再比较重采样、样本权重和课程顺序。验收必须同时看整体指标与 tail-slice 指标，防止平均分上升但高风险长尾退化。

**差距在哪**：新手以为问题是“量不够”。高手知道问题是“质不真”。面试官想听的是你真实踩过的坑。

### Q：预训练数据清洗方法？

> 来源：阿里 AI Agent 开发一面【[MiniMax - 大模型算法岗（后训练 / SFT / RL 方向，独角兽）](https://www.nowcoder.com/discuss/925527528259743744)追问：数据清洗时，你如何筛选低质量样本？用过哪些启发式规则或模型过滤？】【[MiniMax - 大模型算法岗（后训练 / SFT / RL）](https://www.nowcoder.com/discuss/926272883872075776)追问：低质数据筛选的启发式规则或模型过滤方法？】

**新手答**：“去重，过滤脏数据。”

**高手答**：

预训练数据清洗要解决三类问题：

| 类型 | 典型表现 |
|------|---------|
| 脏数据 | 乱码、HTML 残留、脚本片段、异常符号、错误编码 |
| 重复数据 | 完全重复、近重复 |
| 低质量数据 | 广告、灌水、模板文、机器翻译残片、拼接错乱文本 |

处理流程分三步递进：

1. **规则清洗**：去标签、过滤控制字符、长度约束、语言检测
2. **质量过滤**：困惑度过滤、分类器识别垃圾文本、关键词规则
3. **去重**：MinHash、SimHash、LSH 做近重复检测

真正影响模型上限的，很多时候不是模型结构，而是预训练数据质量。

**差距在哪**：新手只说了两个词。高手按“规则→统计→算法”的层次把清洗逻辑讲清楚了。面试官考的是你有没有处理过大规模数据的经验。

### Q：自动标注系统的主要难点是什么？如何设计模型预标注、置信度分流和人工复核闭环？

> 来源：[字节 Seed 具身数据一面](https://www.nowcoder.com/feed/main/detail/657dfac8ca5c49f28492a1110b95f7cd)【[百度具身研发一面](https://www.nowcoder.com/feed/main/detail/258695ecdfbb464790fc8ae55c9f1661)追问：标注相关，有做过自动化标注吗？】

**新手答**：“让大模型先标，低置信度的交给人工。”

**高手答**：

难点不只是准确率，而是**置信度未校准、错误具有相关性、分布持续变化**。模型可能对系统性错误非常自信，只审低置信样本会把最危险的错误直接放行。

生产闭环应这样拆：

1. 先按版本化 schema 做规则校验和模型预标注，保存模型、Prompt、输入和候选标签版本。
2. 用校准集把分数转成可解释风险；高风险或高业务成本样本强制人工，中间区间多人复核，低风险区也保留随机抽检。
3. 植入金标样本和重叠样本，区分模型错误、标注员漂移和规范歧义；分歧进入仲裁队列，不能用多数票静默覆盖。
4. 人工修正回流时保留原预测与原因码，按错误簇选下一轮主动学习样本，避免只重复采最容易的数据。
5. 上线后监控输入分布、分标签通过率、抽检错误率和下游任务指标；漂移后先降级到人工，不自动放宽阈值。

关键原则是“模型提速，人工定义事实边界”。自动标注输出是候选，不是天然 ground truth。

**差距在哪**：新手只有一个阈值，高手能设计带版本、校准、随机审计、仲裁和漂移回退的质量系统。

### Q：SFT 数据字段如何映射？instruction 与 input 重叠时如何定义清洗和拼接契约？

> 来源：[大方云图研发实习一面](https://www.nowcoder.com/feed/main/detail/a9a40feb4e1e4d0ca7c3f8c3ba67d487)【[阶跃星辰（Stepfun）- 大模型算法岗（Post-train）](https://www.nowcoder.com/discuss/926273007276814336)追问：SFT 数据中指令与输入字段重叠的处理？】

**新手答**：“把 instruction、input 和 output 拼成一段文本；重复内容去掉即可。”

**高手答**：

先定义一种**规范样本**，再适配外部字段。内部可以统一为 `messages`，也可以统一为 `prompt/completion`，但必须保留 `sample_id`、来源、数据版本和任务类型。字段映射是确定性 ETL，不能让训练脚本现场猜语义。

`instruction` 与 `input` 重叠时先判断角色：

- `instruction` 是稳定任务要求，`input` 是本次实例数据：即使词面重复，也应保留角色边界；
- `instruction` 已经完整内嵌实例数据：规范化后清空 `input`，避免重复喂两遍；
- 两者局部冲突：进入隔离/人工规则，不按“后字段覆盖前字段”处理；
- 多轮数据：转为带 `role` 的消息，不能把历史轮次压成一个无结构字符串。

[TRL 当前 SFTTrainer 文档](https://huggingface.co/docs/trl/sft_trainer)区分 standard/conversational、language-modeling/prompt-completion 数据，并分别支持 completion-only 与 assistant-only loss。工程上应先用目标模型的 chat template 渲染，再检查 BOS/EOS、角色标记、截断和 loss mask；`assistant_only_loss` 还依赖 chat template 正确提供 generation 标记。

Packing 不是天然的样本隔离保证。应结合 TRL 的[内存优化说明](https://huggingface.co/docs/trl/reducing_memory_usage)验证 packing strategy、样本边界和 attention/loss mask：`wrapped` 会把无关样本拼入同一序列，padding-free 模式也需要兼容的注意力实现；若边界或 mask 配错，后一个样本就可能读取前一个样本或继承错误标签区域。

发布前对固定样本做渲染快照、token 级 decode 回放和 hash 归档。否则同一份 JSONL 换 Tokenizer 或模板后，实际训练目标已经变了却无法追踪。

**差距在哪**：新手把字段映射当字符串拼接，高手把它当版本化的数据契约，并能解释角色、模板、截断和 loss 区域。

### Q：Agent 工具调用怎么训练？训练集该包含什么？数据怎么来？

> 来源：阿里 AI Agent 开发一面

**新手答**：“找一些工具调用的例子做微调。”

**高手答**：

训练集至少要覆盖**三类样本**：

1. **该调用工具的**——正样本
2. **不该调用工具的**——只教“会调用”不够，还得教“什么时候不要调”
3. **多工具串并联调用的**——复杂场景下的编排能力

数据来源一般有**四种**：

| 来源 | 做法 | 特点 |
|------|------|------|
| 人工标注轨迹 | 问题 → 思考 → 工具选择 → 参数 → 结果，整合成监督样本 | 质量高，成本大 |
| 线上日志回放 | 从高质量人工操作或已有系统中抽取工具调用链 | 真实，但需清洗 |
| 规则合成数据 | 用模板生成标准调用样本 | 量大，但多样性差 |
| 模型自举 | 用强模型生成轨迹，再人工检验修正 | 扩量快，需质检 |

真正关键的是**负样本和边界样本**——参数缺失、工具返回空、多个工具都可用但优先级不一……这些不补，模型上线很容易乱调。

**差距在哪**：新手只想到了正样本。高手覆盖了正/负/复杂三类样本和四种数据来源。面试官考的是你理不理解模型是怎么学会使用工具的。

### Q：训练数据标注粒度应该越细越好还是按任务适配？如何权衡成本、信息量和泛化？

> 来源：[字节 Seed 具身数据一面](https://www.nowcoder.com/feed/main/detail/657dfac8ca5c49f28492a1110b95f7cd)

**新手答**：“越细越好，细粒度标签包含的信息更多。”

**高手答**：

粒度不是越细越好，而要与**模型的决策单元和评测单元**对齐。具身数据可以按 Episode、子任务、动作段或 Frame 标；客服数据可以按会话、Turn、意图或槽位标。粒度过粗会把多个决策混成一个标签，定位不了失败步骤；粒度过细则增加成本和歧义，还可能让模型只学局部动作，丢失长程目标。

我会先定义分层 schema：

```text
任务层：目标、成功条件、风险等级
阶段层：子任务、开始/结束边界、依赖关系
动作层：动作、参数、Observation、结果
帧层：时间戳、传感器状态、质量标记
```

然后用小规模试标比较三件事：标注员一致性、下游指标增益、单位样本成本。只有更细标签能稳定提升错误归因、策略学习或关键切片指标时才保留；否则让细粒度数据作为派生视图，而不是主事实源。[LeRobotDataset v3](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)把多模态时序数据、Episode 边界和检索元数据分开，正好说明“存储粒度”和“训练采样粒度”可以解耦，但这只是公开格式示例，不是通用最优答案。

**差距在哪**：新手把标签数量当信息量，高手会从学习目标、边界歧义、标注成本和分层复用判断粒度。
