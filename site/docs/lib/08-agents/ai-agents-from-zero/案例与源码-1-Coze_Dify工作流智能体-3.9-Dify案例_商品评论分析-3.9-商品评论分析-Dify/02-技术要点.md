### 技术要点

- **对话流（Chatflow）选择**：本案例需要多次向用户输出（如「正在分析」、最终报告），因此使用 Chatflow 而非 Workflow；Chatflow 支持在流程中任意位置插入「直接回复」节点，且无结束节点限制。
- **文件输入**：开始节点配置为接收 `input_file`（CSV），用户上传商品评论数据后触发全流程。
- **文档与文本处理链路**：文档提取器 → 提取文本 → 切分元数据 → 提取元数据，将 CSV 转为结构化元数据（含 product_title、asin、星级统计等）。
- **大模型分析**：「分析和建议」节点通过系统提示词约束角色（淘宝产品分析师）、分析原则（客观、系统、解决导向）、分析维度（产品/服务/物流/价格）及输出格式（产品分析 + 选品改进建议），保证输出结构化且可复用。
- **代码节点**：汇总阶段用 Python 将 `meta_data` 与 `analysis_and_suggestion` 合并为 `final_result`，便于后续「整理输出」与「输出最终结果」使用。
- **结构化展示**：「整理输出」节点再次调用大模型，按固定 Markdown 模板（一图二链三数量四分析五建议）格式化，最终通过「输出最终结果」呈现给用户。
