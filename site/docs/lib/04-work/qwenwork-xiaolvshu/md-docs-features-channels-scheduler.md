# 定时任务 (/docs/features/channels-scheduler)

千问办公定时任务统一在云端调度：设备休眠或关机时，已到期的任务仍会按计划触发。仅当任务使用本地连接器（浏览器自动化、本地应用操作）时，才要求执行设备处于唤醒且联网状态。

## 调度与运行前提 [#调度与运行前提]

| 项目      | 当前公开说明                                           |
| ------- | ------------------------------------------------ |
| 调度位置    | 云端统一调度，不依赖本机浏览器或客户端在线                            |
| 设备休眠或关机 | 任务仍会在云端按计划触发                                     |
| 本地连接器任务 | 使用浏览器自动化、本地应用操作等本地连接器时，要求设备唤醒且联网；可在桌面端开启“保持系统唤醒” |
| 时间与时区   | 按任务页面中的计划与时区配置                                   |
| 会话关系    | 每次触发新建一个独立对话，与日常对话上下文分开，并消耗 Credits              |
| 任务数量    | 无硬性上限                                            |
| 执行时长    | 无固定限制                                            |

  早期资料按 Web 云端与桌面本地两套定时任务分别描述；最新公开口径为统一云端调度。两端的任务列表、创建入口和配置项仍以当前端页面为准。

## 适合定时运行的任务 [#适合定时运行的任务]

* 每天或每周生成行业简报、工作汇总和经营报表；
* 定期追踪竞品、公开信息或指定指标；
* 在固定日期准备会议材料或提醒；
* 按周期读取明确目录中的最新数据；
* 将已验证结果发送到已授权的邮件或 IM 会话。

任务应具备稳定数据源、明确时间范围、可检查输出和固定接收位置。需要临场判断、数据来源不稳定或会产生高风险外部操作的任务，不适合直接无人值守运行。

## 创建方式 [#创建方式]

    Web 文档列出三种方式：

    * 在“定时任务”页面填写名称、计划时间和执行指令；
    * 在普通对话中直接说明“什么时候做什么”；
    * 从常见任务模板开始，再修改时间和要求。

    保存后，从任务列表检查启用状态和下一次执行时间。当前输入框若提供附件、模型或发送渠道，也应在保存前逐项核对。

    桌面端可以在对话中要求把当前流程转为定时任务，也可以从管理页面填写：

    * 任务名称；
    * 计划时间；
    * 完整 Prompt；
    * 工作目录和附件（可选）。

    复杂任务先在普通桌面对话中完整跑通，再固化 Prompt、目录和工具配置。

## 计划时间 [#计划时间]

| 类型  | 执行规则             | 示例               |
| --- | ---------------- | ---------------- |
| 不重复 | 在未来某个日期和时间执行一次   | 会前资料准备           |
| 间隔  | 距上次运行达到固定时长后再次执行 | 每 30 分钟检查一次      |
| 每小时 | 每小时在指定分钟触发       | 每小时第 15 分钟       |
| 每天  | 每天固定时间触发         | 每天 09:00 生成早报    |
| 每周  | 在所选星期和时间触发       | 工作日 09:00        |
| 每月  | 在所选日期和时间触发       | 每月 1 日 09:00     |
| 自定义 | 使用当前端支持的周期表达式和时区 | 每天 09:00 与 18:00 |

自然语言可以帮助生成计划，但保存前必须检查工作日、月末、节假日和时区转换。“每月最后一个工作日”等复杂表达不保证在所有端都按同一种规则执行，正式使用前先做临近时间测试。

## 创建与启用流程 [#创建与启用流程]

    ### 定义输入 [#定义输入]

    写清要读取的数据源、目录、筛选条件、时间范围和无数据时的处理方式。

    ### 定义输出 [#定义输出]

    指定标题、字段、格式、文件名、保存位置和是否发送到外部渠道。

    ### 确认本地依赖 [#确认本地依赖]

    依赖本地文件、浏览器或系统应用的任务会使用本地连接器，执行时要求设备唤醒且联网；其余任务在云端调度，不依赖本机状态。

    ### 手动演练 [#手动演练]

    用真实但低风险的数据运行一次，记录单次积分消耗、耗时、权限和输出结果。

    ### 临近时间测试 [#临近时间测试]

    设置一次临近触发，验证时区、会话、通知、目标位置、重复写入和失败状态。

## 执行记录与管理 [#执行记录与管理]

* 启用或停用不会改变已经生成的历史会话；
* 编辑可以修改名称、计划时间和执行指令；
* “立即运行”额外执行一次，不影响原定计划；
* 删除任务后不可恢复，删除前应确认该计划不再需要执行；
* 每次运行都应能从执行记录进入独立会话，查看运行中、成功或失败；
* 独立运行不会自动继承其他日常对话的上下文，固定资料和规则必须写进任务配置。

使用本地连接器的任务要求设备唤醒且联网；重要任务可以在桌面端开启“保持系统唤醒”，但仍需处理断网、登录过期、客户端退出和系统更新。

## 结果保存与发送 [#结果保存与发送]

结果默认保存在对应任务会话。需要发送到邮件、钉钉或其他 IM 会话时，先完成连接器或频道授权，并在执行指令中明确接收对象和发送方式。

  先用测试收件人或测试群验证内容、附件和失败重试。删除、覆盖、审批、发布和批量发送不应在第一版无人值守任务中启用。

## 上线检查 [#上线检查]

1. 用唯一键、日期范围或运行批次避免重复写入；
2. 数据为空、字段缺失或来源异常时停止并记录；
3. 对数量、金额、时间和资源设置上限；
4. 检查积分不足、登录过期和权限失效时的行为；
5. 为外部接收者设置测试、确认和撤销路径；
6. 定期检查任务是否仍有业务责任人和有效数据源。
