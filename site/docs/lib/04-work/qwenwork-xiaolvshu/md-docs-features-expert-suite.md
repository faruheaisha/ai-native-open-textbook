# 专家套件 (/docs/features/expert-suite)

专家套件把多个 Skill、数据连接、工作流和输出标准组合成一套领域或岗位方案。它适合将已经验证的方法从个人试用推广到团队，而不是替代专业责任人。

## 专家套件与 Skill [#专家套件与-skill]

| 维度    | Skill           | 专家套件                 |
| ----- | --------------- | -------------------- |
| 定义    | 一项专业知识或工作方法     | 完整方案包，组合 Skill、连接和标准 |
| 解决问题  | 让 AI 学会怎么完成一类任务 | 让团队统一安装和使用一套方案       |
| 合适阶段  | 小范围探索和验证        | 验证完成后的分发与治理          |
| 典型使用者 | 个人或小组           | 团队、岗位或行业场景           |

安装专家套件不会自动获得更多权限。它能读取或写入什么，仍取决于成员身份、连接器、第三方账号和显式授权。

## 创建与定制 [#创建与定制]

当前有两种主要方式：

* 在专家套件页面选择“通过 QwenWork 创建”，用自然语言描述岗位、任务、数据、流程和标准；
* 对已经安装的套件选择“定制此套件”，由千问办公加载对应配置并按要求修改。

创建前先用 Skill 和真实任务验证方法。套件应写清适用范围、输入、数据连接、执行顺序、输出标准、人工关口、失败处理和版本负责人。

## 上传与分享 [#上传与分享]

套件可以导出为 `.zip` 文件并发送给同事。公开页面要求压缩包中至少包含以下一种清单结构：

```text
.qwen-plugin/plugin.json
```

或：

```text
.claude-plugin/plugin.json
```

`plugin.json` 必须包含 `name` 字段。上传前应解压检查清单、脚本、Skill、外部连接、依赖和默认操作，不能只根据文件名信任套件。

  团队使用前仍需完成来源审核、权限检查、正常与异常样本测试、版本记录和责任人确认。涉及法律、财税、投资或人事判断的套件不能代替专业复核。

  较新扩展文档明确说明：把已定制套件更新到创作者发布的新版本时，会以新版本为准并覆盖个人修改。更新前先导出当前套件，记录差异，并准备回退包。

## 公开页面列出的内置方向 [#公开页面列出的内置方向]

| 方向    | 示例                  |
| ----- | ------------------- |
| 产品与设计 | 产品管理、产品设计           |
| 法律与财税 | 企业法务、企业财税、合同管理      |
| 咨询与营销 | 咨询交付、市场营销           |
| 投资与金融 | 投研分析、投行业务、股权投资、财富管理 |
| 科技服务  | 科技服务助手              |

实际套件数量、名称和可用范围以当前专家套件页为准。

## 套件包含什么 [#套件包含什么]

* **快捷命令**：在对话中通过 `/` 调用的预设入口；
* **数据连接**：套件预配置或依赖的外部连接器；
* **知识技能**：领域知识、方法、判断标准和工作流程。

一个任务可以组合多个套件，但组合越多，权限、用量、冲突和责任边界越复杂。优先选择覆盖当前目标的最小组合。

## 上线检查 [#上线检查]

1. 套件来源和维护者是否可信；
2. 会安装或调用哪些 Skill、连接器和脚本；
3. 会读取、传输或写入哪些数据；
4. 哪些步骤会产生发送、删除、审批或发布；
5. 正常样本、错误样本和权限不足时如何处理；
6. 如何更新、回退、停用和移除；
7. 谁负责专业准确性和最终验收。
