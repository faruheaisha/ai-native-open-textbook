# 岗位路线图 (/docs/playbooks/role-roadmap)

## 选择首个任务 [#选择首个任务]

一个适合试点的岗位任务应当重复发生、输入容易获得、输出有稳定格式、结果能被责任人快速检查，并且错误不会立即产生不可逆后果。

## 产品经理 [#产品经理]

| 阶段 | 场景        | 交付物           |
| -- | --------- | ------------- |
| L1 | 用户访谈整理    | 痛点、原话、待验证问题   |
| L2 | 反馈聚类与版本复盘 | 分类、影响范围、证据表   |
| L3 | 竞品与机会跟踪   | 对比表、定期简报、机会地图 |

人工关口：不能把模型推断写成用户原话，产品决策由负责人承担。

## 运营与市场 [#运营与市场]

| 阶段 | 场景     | 交付物           |
| -- | ------ | ------------- |
| L1 | 已审内容改写 | 平台草稿、标题池、素材清单 |
| L2 | 内容排期   | 选题表、证据包、内容日历  |
| L3 | 内容雷达   | 多源监控、评分、发布复盘  |

推荐从[内容雷达](https://qwenwork.org)和[爆款内容拆解](https://qwenwork.org)开始。

## 销售与售前 [#销售与售前]

| 场景    | 交付物            | 主要风险       |
| ----- | -------------- | ---------- |
| 会后整理  | 需求、异议、待办和负责人   | 把推测写成客户承诺  |
| 客户研究  | 画像、公开动态、机会假设   | 同名主体与过时信息  |
| 方案与演示 | 大纲、演示脚本、FAQ    | 虚构能力、价格和案例 |
| 跟进工作流 | CRM 草稿、提醒、材料更新 | 未确认写入和外发   |

## HR 与行政 [#hr-与行政]

* 制度摘要和 FAQ：必须标注版本日期与适用范围；
* 入职培训：生成学习路径、课件和检查清单，减少员工数据输入；
* 行政采购：使用[企业采购寻源](https://qwenwork.org)，保留下单确认；
* 人事流程：可以检查材料和提醒，不自动做录用、晋升或处罚决定。

## 财务与法务 [#财务与法务]

| 财务场景   | 法务场景      | 人工关口       |
| ------ | --------- | ---------- |
| 发票字段整理 | 条款提取与版本对照 | 金额、主体和原文复核 |
| 预算差异清单 | 风险条款清单    | 口径与风险判断    |
| 月结材料盘点 | 法规与合同底稿   | 申报、签署和专业意见 |

可从[发票制单](https://qwenwork.org)、[合同预审](https://qwenwork.org)和[法规检索](https://qwenwork.org)开始。

## 研发与 IT [#研发与-it]

* 代码和技术文档：架构图、README、模块清单必须与实际代码一致；
* 测试与缺陷：输出测试矩阵、复现步骤和修复建议，合并前仍需评审；
* 发布准备：可以生成变更说明和检查表，部署是独立确认点；
* IT 巡检：只读检查优先，生产权限与事故响应由指定人员控制。

## 部门推广卡 [#部门推广卡]

```text
岗位与场景：[谁在什么工作中使用]
原流程：[步骤、系统、耗时和常见错误]
输入：[文件、字段、权限和质量问题]
输出：[文件、系统记录和通知对象]
验收：[准确、完整、时效和风险标准]
人工关口：[谁确认，什么情况下暂停]
指标：[当前基线、目标值和观察周期]
负责人：[业务、技术和资产维护人]
```

岗位落地的终点不是每个人都会问 AI，而是形成一批新人可复用、负责人可维护、出现问题能追溯的标准工作流。
