# 长期记忆与意识 (/docs/features/memory)

“意识”是千问办公统一管理协作风格、工作手册、用户画像和记忆的模块，入口为“设置 > 意识”。它持续维护使用偏好、工作规范、重要知识和近期对话摘要，让后续任务不必每次从零开始。

  公开说明中的入口为左侧边栏底部的账户头像，进入“设置 > 意识”。不同端、账号和版本可能不一致。当前界面没有入口时，不要自行创建目录来模拟产品能力。

## 两个主开关 [#两个主开关]

| 开关   | 公开说明中的作用                 |
| ---- | ------------------------ |
| 意识模式 | 按定制的协作风格工作，并启用跨会话记忆与技能进化 |
| 自动记忆 | 自动维护用户画像、长短期记忆并定期触发记忆反思  |

启用自动记忆前，先确认哪些信息可以长期保存，哪些只能停留在当前任务。团队制度、个人偏好和项目临时信息应分开管理。

## 协作风格 [#协作风格]

协作风格是意识模块中的设置项，不是意识目录中的文件。当前公开说明提供四种预设：高效极简（默认）、深思熟虑、温和耐心、果断执行，可在个性化入口中更换。

协作风格只影响默认的沟通和工作方式，不会代替当前任务中的明确要求。任务里说明的格式、范围和约束始终优先于已保存的风格和偏好。

## 意识文件 [#意识文件]

意识内容以文件形式保存在意识页面显示的存储位置，并建立本地检索索引。文件结构以当前界面为准：

| 文件或目录       | 用途                        |
| ----------- | ------------------------- |
| `AGENTS.md` | 工作手册：工作规范和行为准则，可自行编辑      |
| `USER.md`   | 用户画像：基本信息、偏好和习惯，由千问办公自动维护 |
| `MEMORY.md` | 长期记忆：跨会话持久保存的重要知识和结论      |
| `memory/`   | 短期记忆：按天记录的对话摘要和临时笔记       |

工作手册适合写入长期稳定、可以明确执行的规则；用户画像和记忆由自动维护，可能存在遗漏或理解偏差，应定期检查准确性和时效。长期保留的信息应沉淀到长期记忆或正式文档，不要只留在短期记忆中。

## 语音记忆 [#语音记忆]

语音记忆供系统级语音输入使用，记录常用表达和纠错偏好，例如产品名、人名、公司名和专业术语的正确写法。它服务于语音识别准确度，与面向对话协作的用户画像分工不同。

## 进化动态 [#进化动态]

意识页面以折线图展示记忆数量变化和当前记忆总数，可按天、周、月切换范围；当日视图展示审查、记忆、技能、反思的次数，并按时间列出记忆反思、长期记忆等更新记录。进化动态用于观察自动维护的活跃度，不等于记忆质量的证明。

## 搜索索引与重建 [#搜索索引与重建]

意识内容以文件形式保存，并建立本地检索索引。导入意识目录、手动修改文件、文件存在但无法检索或恢复备份后，可以使用“重建搜索索引”重新扫描意识目录并生成索引。

重建索引只刷新检索数据：它不代替用户画像、长期记忆或短期记忆，也不会新增记忆，更不能被当作记忆内容的备份。

## 备份与恢复 [#备份与恢复]

意识页面支持导出和导入整个意识目录，可用于多设备迁移或备份，但不应理解为产品已提供自动同步开关。

在修改协作风格、工作手册或记忆之前：

1. 使用当前界面提供的导出能力备份整个意识目录；
2. 记录导出时间、设备和当前客户端版本；
3. 检查备份中是否包含不应跨设备流转的数据；
4. 恢复后检查手册、画像和记忆内容，检索异常时重建索引，并用一个低风险任务验证规则和记忆是否正确；
5. 不把导出包上传到公开网盘或无权限控制的渠道。

## 不可逆操作 [#不可逆操作]

| 操作     | 影响                                         |
| ------ | ------------------------------------------ |
| 重置协作风格 | 清除当前协作风格配置，需要重新选择或设置                       |
| 重置工作手册 | 用初始模板覆盖当前 `AGENTS.md`，自行添加的规范可能丢失          |
| 清空记忆   | 删除 `USER.md`、`MEMORY.md` 和所有记忆日志文件，并重建搜索索引 |

  清空记忆和重置工作手册会删除或覆盖现有内容。执行前保存备份，并确认备份中没有密钥、密码、验证码或不必要的个人敏感信息。

## 使用原则 [#使用原则]

* 当前任务中的明确要求优先于过去保存的偏好；
* 不在意识文件中保存密码、验证码或访问密钥；
* 用户画像、长期记忆和短期记忆由自动维护，可能存在遗漏或理解偏差；
* 正式业务知识不应只保存在记忆中，重要结论应进入文档、网盘或知识库。

## 记忆治理建议 [#记忆治理建议]

* 不把一次性账号、密钥和访问令牌写进长期记忆；
* 事实、偏好和推断分开记录，并保留来源和更新时间；
* 过期项目和离职成员信息应按组织规则清理；
* 重要决策不能因为“系统记得”就跳过原始材料核验；
* 定期检查自动写入内容是否仍准确、必要和有权保存。
