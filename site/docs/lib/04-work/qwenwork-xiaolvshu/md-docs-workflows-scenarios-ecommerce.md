# 电商场景 (/docs/workflows/scenarios/ecommerce)

电商场景的重点，是把数据、商品和内容转成可以执行、复核和继续迭代的运营动作。完整链路分成三段：调研数据与分析选品、批量生成商品素材、经营复盘与优化建议。

  chart="flowchart LR

  B --> C[候选商品与证据]
  C --> D[小样本素材]
  D --> E\{品牌与平台验收\}
  E -->|通过| F[批量生成]
  F --> G[经营数据复盘]

## 三段工作流 [#三段工作流]

| 阶段    | 推荐输入                   | 交付物                  | 人工关口              |
| ----- | ---------------------- | -------------------- | ----------------- |
| 调研与选品 | 品类范围、平台数据、销量、评价、价格带和成本 | 候选库、证据链接、机会与风险       | 复核数据日期、样本偏差和供应可行性 |
| 商品素材  | 商品事实、品牌规范、人群与平台尺寸      | 主图、详情页、活动图和卖点文案      | 核对版权、禁用词、规格与商品一致性 |
| 经营复盘  | 曝光、点击、转化、销售、退款、库存和投放   | 指标看板、异常清单、关键词投放优化与假设 | 复算指标，不把相关性直接写成原因  |

## 输入契约 [#输入契约]

```text
业务决定：本轮要选择商品、制作素材，还是优化现有经营？
范围：平台、店铺、品类、地区和统计时间。
数据：字段说明、币种、成本口径、缺失值和更新时间。
商品事实：规格、成分、库存、资质、价格与不得改写的信息。
品牌要求：语气、视觉规范、禁用表达和素材版权。
输出：候选数量、素材尺寸、报告格式与命名方式。
权限：允许读取、下载和生成什么；发布、改价与上下架另行确认。
```

## 执行顺序 [#执行顺序]

    ### 建立可比较的数据表 [#建立可比较的数据表]

    统一商品标识、价格周期、销量口径和评价时间，保留原始表与清洗记录。无法确认的字段保持空值或标为待核验。

    ### 形成候选库而不是直接下结论 [#形成候选库而不是直接下结论]

    对候选商品列出机会证据、成本或供应约束、负面反馈和仍需验证的问题，由负责人决定是否进入打样或采购。

    ### 先做一个商品的小样本 [#先做一个商品的小样本]

    一套商品素材的交付范式是：按使用场景拆分的 4 张系列主图（如产品主视觉、职场通勤、约会时刻、香调卖点）、详情页长图，以及一份 `文案与尺寸规范.md`。先完成一个商品的整套样本，核对规格、平台尺寸、品牌规范和版权，再扩大到同类商品。

    ### 用经营结果更新假设 [#用经营结果更新假设]

    分开呈现事实指标、可能原因和建议动作。每项动作写明负责人、观察周期和判断是否有效的指标。

## 验收清单 [#验收清单]

* [ ] 商品、店铺、平台和统计周期可追溯；
* [ ] 价格、库存、销量和评价都标注查询时间；
* [ ] 选品评分能回到原始字段和计算规则；
* [ ] 素材中的规格、功效和优惠与真实商品一致；
* [ ] 图片、字体、人物与品牌资产具备使用权；
* [ ] 经营建议区分证据、推断和待验证假设；
* [ ] 发布、投放、改价与上下架仍由授权人员最终确认。

  公开页面列出的电商数据能力不代表所有字段、平台和账号始终可用。正式决策前重新核验价格、库存、热度与平台规则，不用一次抓取结果替代业务判断。
