# 场景需求模板 (/docs/community/scenario-intake)

## 提交前先搜索 [#提交前先搜索]

先在站内搜索任务关键词，并查看[案例中心](https://qwenwork.org)、[岗位路线](https://qwenwork.org)和[行业路线](https://qwenwork.org)。如果目标相同，优先在现有方法上补充差异。

## 场景需求卡 [#场景需求卡]

```text
场景名称：[一句话说明要解决的问题]

1. 使用者
岗位或团队：[谁在使用]
使用频率：[每天、每周、每月或偶发]

2. 当前流程
现在怎样完成：[按顺序描述步骤]
会用到哪些系统：[只写系统类型，不提供账号]
耗时与主要困难：[时间、重复、遗漏或质量问题]

3. 输入资料
资料类型：[文档、表格、消息、图片或网页]
典型规模：[文件数、行数、时间范围]
质量问题：[缺字段、格式不一致、重复或过期]

4. 期望交付
最终产物：[文件、表格、消息、页面或系统记录]
使用者：[谁查看、谁继续处理]
时效要求：[什么时候需要]

5. 验收标准
准确性：[哪些事实必须正确]
完整性：[必须包含哪些字段]
格式：[结构、文件类型和命名]
成功指标：[节省时间、降低错误或提高采用率]

6. 安全边界
敏感数据：[只说明类型]
允许操作：[读取、生成草稿、写入或发送]
人工关口：[谁在什么动作前确认]
禁止事项：[不能访问、修改或发布什么]

7. 已尝试方法
尝试过什么：[提示词、模板或人工流程]
失败表现：[具体错误或不满意之处]

8. 来源与复用
是否基于现有案例：[否，或填写站内案例标题]
外部来源类型：[仓库、网页、原始投稿或无]
权利状态：[自有、已授权、明确许可、仅可引用或待确认]
可公开贡献：[正文、脱敏样例、代码、图片或只提供方法]
期望署名：[公开名称；不要填写不希望公开的身份信息]
```

## 评估标准 [#评估标准]

| 维度   | 适合进入案例验证的信号          |
| ---- | -------------------- |
| 真实性  | 来自正在发生的工作，而非想象功能     |
| 复用性  | 多人或多次会遇到类似问题         |
| 可验证  | 有清晰输入、产物和验收标准        |
| 可控性  | 权限、数据和外部操作边界明确       |
| 产品匹配 | 千问办公已有能力能够覆盖主要步骤     |
| 权利清楚 | 清楚区分自有、授权、引用和不可迁移的材料 |

## 后续处理 [#后续处理]

完整需求先进入候选队列和小样本验证，不会自动获得案例状态或进入导航。无法解决时也应记录缺失能力、手工替代方案和停止原因。通过来源、权利、脱敏和完整性审核后，再使用[案例正文模板](https://qwenwork.org)整理为独立教程；完整流程参见[案例贡献与维护](https://qwenwork.org)。
