# 文档起草与修订 (/docs/workflows/office-docs)

文档任务的难点通常不是“写出文字”，而是保持事实、语气、结构和使用目的的一致。

“制作可编辑标准样式 Word”是常见的生成内容场景。合同、方案、通知或复盘都应沿用同一原则：先提供事实和格式约束，再生成可继续编辑的文件，并在使用前完成专业复核。

## 起草前准备 [#起草前准备]

* 读者是谁，会用它做什么决定；
* 哪些事实来自已提供资料；
* 哪些内容可以概括，哪些必须逐字准确；
* 需要沿用的模板、术语和格式；
* 哪些信息缺失时必须标记待确认。

## 示例：撰写项目复盘 [#示例撰写项目复盘]

```text
请根据附件中的项目计划、周报和验收记录，生成一份项目复盘 Word 文档。

读者：部门负责人和下一个项目的执行团队。
结构：目标与范围、关键结果、计划偏差、原因、有效做法、改进动作。
规则：所有数字必须能在附件中找到；信息冲突时列出冲突来源，不自行选择。
改进动作表必须包含负责人角色、完成时间、验证方式。
文风：简洁、客观，不使用宣传性语言。
完成后输出事实核对表，并保存为“项目复盘-v1.docx”。
```

## 修订策略 [#修订策略]

不要只说“写得更好”。使用可定位反馈：

* “第二节重复结论，请合并并保留原始数据”；
* “把没有证据的原因判断改为待验证假设”；
* “面向管理层，把前三项风险提前到摘要”；
* “保留标题层级，不改变公司模板字体和页眉”；
* “修订后列出改动点，不直接覆盖无法确认的数字”。

## 验收清单 [#验收清单]

* [ ] 标题、日期、组织和项目名称正确；
* [ ] 数字、姓名和时间可以追溯到输入；
* [ ] 事实、判断和建议没有混为一谈；
* [ ] 没有泄露不应出现的内部信息；
* [ ] 文件可打开、可编辑，目录和样式完整；
* [ ] 改进动作可执行并可验证。
