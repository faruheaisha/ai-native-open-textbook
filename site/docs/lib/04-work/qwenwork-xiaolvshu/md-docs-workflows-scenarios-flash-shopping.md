# 闪购场景 (/docs/workflows/scenarios/flash-shopping)

闪购经营受实时库存、履约能力、平台活动和门店成本共同影响，菜市场卤味店、甜品轻食档口、茶饮门店等淘宝闪购中小商家是典型业态。场景分成商品管理、活动与利润、经营与商品诊断、品牌内容与视觉四段；每一段都应先生成建议，再由门店负责人确认真实操作。

## 四段工作流 [#四段工作流]

| 阶段     | 需要先准备                 | 推荐产物             | 停止条件          |
| ------ | --------------------- | ---------------- | ------------- |
| 商品上下架  | 商品清单、实时库存、营业时间和平台状态   | 待上架、待下架与需补货清单    | 库存或平台状态无法实时确认 |
| 活动利润测算 | 售价、成本、平台佣金、补贴、配送与退款口径 | 方案对比、盈亏平衡点和敏感性分析 | 活动规则或成本字段缺失   |
| 商品诊断   | 销售、曝光、转化、缺货、退款和差评     | 爆品、低效品、断货损失与改进假设 | 数据周期不一致或样本过少  |
| 内容与视觉  | 品牌定位、真实商品信息、门店照片和平台尺寸 | 商品文案、店铺图和视觉升级清单  | 版权、功效或价格无法确认  |

## 先算清活动账 [#先算清活动账]

不要只比较“折扣力度”。至少把以下项目放进同一口径：

```text
单笔贡献 = 实收金额
         - 商品与包装成本
         - 平台佣金及服务费
         - 商家承担的优惠
         - 商家承担的配送或补贴
         - 预计退款与损耗
```

同时给出客单价、订单量和退款率变化时的结果区间。来源缺少的成本不得按行业平均值静默补齐，应列入待确认项。

## 执行与确认 [#执行与确认]

    ### 读取并校验门店状态 [#读取并校验门店状态]

    核对门店、商品 ID、规格、库存更新时间和营业状态。名称相似但 ID 不同的商品不能合并处理。

    ### 生成动作草案 [#生成动作草案]

    把“建议上架、建议下架、建议补货、建议观察”分开，说明触发证据和可能影响，不直接操作平台。

    ### 测算活动与经营影响 [#测算活动与经营影响]

    对每个方案展示完整成本、最低可接受订单量和风险条件，由负责人选择是否采用。

    ### 单独授权平台操作 [#单独授权平台操作]

    如果使用浏览器或连接器执行上下架、改库存或发布内容，先展示最终商品、数量、价格和目标账号，操作后回读状态并保存变更清单。

  商品库存、营业状态和平台规则可能在任务执行期间变化。缺货接单、错误下架、错价和不符合活动规则都会产生真实损失；最终提交前必须重新读取状态并由门店负责人确认。

## 验收清单 [#验收清单]

* [ ] 商品 ID、门店、规格和库存更新时间一致；
* [ ] 活动测算包含所有由商家承担的费用；
* [ ] 爆品、低效品和断货损失的定义明确；
* [ ] 分析区分季节、活动和缺货等可能干扰因素；
* [ ] 文案没有虚构商品成分、功效、价格或优惠；
* [ ] 平台操作前后都有状态快照和变更记录；
* [ ] 可以按商品 ID 恢复到操作前状态。
