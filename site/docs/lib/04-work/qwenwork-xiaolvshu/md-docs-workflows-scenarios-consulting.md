# 咨询场景 (/docs/workflows/scenarios/consulting)

咨询场景要把零散信息变成可追溯、可评审的交付成果。完整链路包括客户资料与数据提取、行业调研与对标、风险识别与问题诊断、建议与报告生成。

## 四段交付链 [#四段交付链]

| 阶段    | 输入               | 中间产物                    | 评审问题              |
| ----- | ---------------- | ----------------------- | ----------------- |
| 资料与数据 | 访谈、文档、表格、合同和业务记录 | 资料目录、事实表、冲突与缺失清单        | 是否完整、是否有权限、口径是否一致 |
| 行业与对标 | 研究问题、市场范围、竞品和标杆  | 来源表、对比维度、事实与推断          | 来源能否直接支持结论        |
| 风险与诊断 | 合同条款、经营数据、流程和约束  | 风险项、证据、等级草案与待验证原因       | 是否越过法律或管理判断责任     |
| 建议与报告 | 已确认事实、分析结论和方案    | Word、PPT 或 HTML 报告及证据附录 | 建议能否执行、验证和回退      |

## 项目输入契约 [#项目输入契约]

```text
客户问题：本项目要支持哪项决策，明确不解决什么。
资料范围：数据室、访谈、系统导出和公开来源的截止日期。
保密等级：可处理、需脱敏、禁止上传和禁止对外检索的内容。
数据口径：组织、产品、地区、币种、周期和异常处理规则。
对标范围：对象、选择理由、维度与来源优先级。
专业责任：法律、财务、合规或技术结论由谁签署。
交付：Word、PPT 或 HTML 的受众、结构、版本和评审节点。
```

## 分阶段执行 [#分阶段执行]

    ### 先建立资料索引 [#先建立资料索引]

    为每份材料记录文件名、版本、日期、所有者、保密等级和可支持的问题。重复、冲突与缺失资料单独列出。

    ### 分开事实、解释和假设 [#分开事实解释和假设]

    事实必须能定位到材料或来源；解释说明证据链；假设同时写明验证方式。不要为了完整叙事填补客户没有提供的信息。

    ### 在形成建议前设置诊断评审 [#在形成建议前设置诊断评审]

    由项目负责人检查问题树、风险等级、对标可比性和替代解释。合同风险只作为审阅线索，不替代律师意见。

    ### 从同一事实底稿生成多种交付 [#从同一事实底稿生成多种交付]

    Word 保留完整方法与证据，PPT突出决策，HTML用于交互展示。三种版本的数字、结论和限制条件必须一致。

## 交付验收 [#交付验收]

* [ ] 客户材料和公开来源都有版本、日期与权限记录；
* [ ] 关键数字可以回到原始表、Sheet 和计算口径；
* [ ] 行业对标说明对象选择和可比性限制；
* [ ] 风险等级有定义，专业结论由责任人确认；
* [ ] 建议包含负责人、资源、里程碑、指标和停止条件；
* [ ] 报告中的事实、推断、假设和未知项明确分开；
* [ ] Word、PPT 与 HTML 版本之间没有数字或结论漂移；
* [ ] 交付前完成脱敏、引用、附件和访问权限检查。

  保密材料、个人信息、商业秘密和受合同限制的数据，应先按项目规则分类。需要浏览器、外部连接器或第三方模型时，必须确认数据是否允许离开原有边界。
