# WorkBuddy 自定义 Skill 教程：创建、测试与复用流程

同一类任务做过几次以后，提示词往往会越写越长。

每次记录灵感，都要重新说明怎么分类、整理成什么格式、保存到哪里。

换个会话以后，这些要求又要再讲一遍。

漏掉其中一句，保存结果就可能和上次不同。

这时候可以考虑创建一个自定义 Skill。

它把一项固定任务的触发方式、处理步骤和输出结果写成可重复使用的规则。

以后遇到同类内容，直接用自然语言表达需求，不必再次复制整段说明。

不过，并非每个提示词都值得做成 Skill。

第一次练习最好选择高频、范围清楚、结果容易检查的任务。

下面就用「记录灵感」为例，完整走一遍创建、测试和修改过程。

## 先确认这项任务是否适合做成 Skill

一项任务适合做成 Skill，通常有几个明显特点。

- 经常重复出现
- 每次处理步骤大致相同
- 输入内容会变化，输出格式相对固定
- 完成结果可以明确检查

记录灵感正好符合这些条件。输入可以是一句话，也可以是一段还没理顺的想法。处理过程基本固定，需要判断内容类型，提取主要想法，补上待验证事项，再保存到指定目录。

第一次不要把灵感、会议纪要、任务管理和文章写作全放进一个 Skill。规则越多，触发范围越容易含糊。先把「收到一条灵感并保存」做稳定，再考虑增加其他能力。

## 创建前写清五项规则

直接说「帮我做一个灵感 Skill」仍然留下很多空白。WorkBuddy 不知道什么话算灵感，也不知道整理后要写入哪里。

创建前先确定下面五项。

**什么时候触发**

用户明确说「记一条灵感」「记录这个想法」或「保存这个创意」时启动。普通聊天里偶然出现「想法」两个字，不要自动写文件。

**会收到什么内容**

输入可能是产品点子、文章选题、工作改进建议或待验证创意。原话有多少就处理多少，不替用户补充不存在的经历和事实。

**怎样整理**

保留原始内容，再提取标题、内容类型、主要想法和待验证事项。信息不足时标记为待补充，不要猜。

**保存到哪里**

提前指定目录和文件格式。保存位置不清楚时，Skill 即使整理得很好，下一次也很难找到。

**完成后反馈什么**

写入成功后返回文件名、保存路径和简短摘要。遇到同名文件时增加序号，不能覆盖旧记录。

这五项确定以后，创建指令就容易写了。

## 直接告诉 WorkBuddy 要创建什么

在对话框中说明 Skill 的用途、触发条件、整理格式和保存规则。可以参考下面这段。

```text
请帮我创建一个用于记录灵感的自定义 Skill。

当我明确说「记一条灵感」「记录这个想法」或「保存这个创意」时触发。普通问答中提到灵感或想法时不要自动保存。

收到内容后，保留用户原话，并整理出标题、内容类型、主要想法、适用场景和待验证事项。没有提供的信息标记为待补充，不要自行编造。

结果使用 Markdown 格式，保存到我指定的灵感记录目录。文件名由日期和简短标题组成，遇到同名文件时自动增加序号，不能覆盖已有记录。

保存完成后，告诉我文件名、保存路径和本次记录的简短摘要。
```

执行完成后，打开技能栏，在已安装目录中查看刚创建的 Skill。

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122812Z-d4104d4f544760e6-45da2183.png)

先检查名称和说明能否让人看懂用途，再看触发方式、保存位置和输出格式有没有写进去。发现目录不对或规则缺失时，先修改 Skill，再开始长期使用。

## 用一条真实任务检查结果

Skill 创建完成后，可以在新会话中输入一条接近日常表达的内容。

```text
记一条灵感，做一个能自动整理会议纪要并同步到知识库的工具。
```

按照原示例，这条内容会被识别为灵感类记录，整理成固定格式，保存到指定位置，并返回处理结果。

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122811Z-0588f402e611887a-9b023f84.png)

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122813Z-92a001000b5b165b-25c94fb1.png)

打开生成的文件，不要只看是否保存成功。

还要确认原话有没有保留，标题是否准确，待验证事项有没有凭空增加，文件是否写进正确目录。

如果记录内容需要长期积累，格式稳定尤其重要。

今天用「主要想法」，明天改成「核心观点」，以后检索和汇总会多出麻烦。

字段名称确定后，除非确有需要，不要频繁改动。

## 再做一次不该触发的测试

只测试成功情况还不够。

一个 Skill 如果触发得太积极，普通聊天也可能被写成文件。

可以在新会话中问一句「怎样判断一个想法是否值得继续做」。

这是一条普通问题，没有明确要求记录。检查 Skill 是否保持安静，只回答问题。

还可以测试几种边界情况。

- 只说「记个灵感」却没有提供正文
- 一次输入两条不同的想法
- 连续保存两个相同标题
- 保存目录暂时无法访问
- 内容里缺少适用场景和待验证事项

没有正文时，应该提示补充内容。两条想法是否拆成两个文件，需要在规则中明确。

同名记录不能覆盖，目录无法访问也应如实反馈。

这些情况跑过一遍，才能知道 Skill 写下的规则是否足够清楚。

## 使用几次以后再修改规则

Skill 不需要第一次就写得很复杂。先用几次，看看问题集中在哪里。

如果标题总是太长，就增加标题字数要求。

如果很多记录都缺少下一步动作，可以增加「待验证事项」字段。

如果误触发较多，就收紧触发条件，只在用户明确要求保存时运行。

修改时一次处理一个问题，并保留原有保存格式。

改完以后重新跑一条正常任务和一条不该触发的普通问题，确认旧功能没有受到影响。

当任务发生明显变化时，也可以单独创建新的 Skill。

灵感记录负责保存想法，会议纪要负责提取决策和待办，文章整理负责处理写作材料。

分开以后，每个 Skill 的用途更容易理解，出错时也方便定位。

## 注意保存和隐私边界

创建会写文件的 Skill 时，要把允许操作的目录写清楚。

默认新增文件，不覆盖旧内容。确实需要修改或删除时，再由用户明确确认。

记录里可能出现客户信息、内部项目和未公开想法。

保存前要考虑目录权限和同步范围，不要因为调用方便，就把敏感内容写进多人共享的位置。

Skill 连接邮箱、消息平台或其他服务时，也要单独检查权限。

只授予当前任务需要的访问范围，并在不再使用时及时停用连接。

## 写在最后

第一次创建个人 Skill，可以从一项每周都会重复的工作开始。

先写清什么时候触发、怎样处理、保存到哪里和完成后返回什么，再让 WorkBuddy 创建。

创建完成后，用一条真实任务测试保存结果，再用一条普通问题检查它会不会误触发。

发现问题就改一条规则，重新测试。等格式稳定、触发准确以后，再把这项任务交给 Skill 长期处理。
