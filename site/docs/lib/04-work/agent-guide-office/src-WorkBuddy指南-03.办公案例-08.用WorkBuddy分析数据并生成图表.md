# WorkBuddy 分析 Excel 数据并生成图表：完整实操教程

手里有一张 Excel 表，并不等于已经有了结论。

经营分析真正花时间的地方，通常是确认字段、统一统计口径、选择图表，再把数字写成别人能看懂的说明。

表格不大时，手动处理还能应付。数据行数增加，或者每个月都要重复做一遍，同样的筛选、汇总和制图就会占去不少时间。

WorkBuddy 可以直接读取 Excel 和 CSV 文件，根据要求统计数据、生成图表并整理报告。

如果数据还没有汇总成表，也可以让它先搜集公开信息，再生成可视化结果。

这篇教程分别走一遍这两种情况。

## 先把要回答的问题说清楚

拿到一张销售明细表以后，先别急着要求「分析一下」。

分析销售额、利润、订单量和客单价，会得到完全不同的结果。

按月份统计可以看变化，按产品线统计适合比较业务表现，按地区拆分又会出现另一组差异。

问题没有说清楚，WorkBuddy 只能替你挑一个方向，生成的图表未必能用于眼前的汇报。

开始前，先确定四件事。

- 这次要看的指标
- 需要按什么维度统计
- 数据覆盖哪个时间范围
- 最后要图表、文字结论还是完整报告

图表类型也可以提前指定。如果暂时拿不准，可以先说明想比较什么，再让 WorkBuddy 推荐图表。

柱状图适合比较不同产品或地区，折线图适合观察一段时间内的变化。

图表形式要跟着问题走，没必要为了页面热闹，把同一组数据画成好几种样子。

## 把 Excel 或 CSV 文件交给 WorkBuddy

已经有数据文件时，可以直接把 Excel 或 CSV 拖进对话，也可以告诉 WorkBuddy 文件所在的路径。

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122814Z-dbdcf71639a6a200-77654d16.png)

文件导入后，建议先让它确认工作表、字段名、数据行数和时间范围。这一步很简单，却能提前发现不少问题。

例如日期列被识别成文本，销售额里混有空值，利润字段使用了不同单位，都会影响后面的统计。

先把数据范围看明白，再开始画图，检查起来会轻松很多。

第一条指令可以这样写。

```text
请读取我上传的销售数据，先不要生成图表。

请列出工作表名称、字段名称、数据行数和日期范围，并检查日期、销售额、利润和产品线字段是否存在空值或明显异常。

如果发现问题，请列出所在字段和对应行，不要自行修改原始数据。
```

看到字段和异常清单以后，再下达正式的分析任务。

```text
请读取这份销售数据，按月份统计各产品线的销售额和利润。

销售额使用柱状图展示，利润变化使用折线图展示。图表中保留单位和月份，并补充一段结论，说明表现最好的产品线、变化最明显的月份和需要继续核查的异常数据。

请同时输出汇总表和图表文件，不要修改原始数据文件。
```

这条指令同时说明了指标、统计维度、图表形式和交付内容。

WorkBuddy 收到以后，可以读取数据、完成汇总并生成图表。

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122815Z-b86df39034d178cb-241b26e5.png)

![](https://vtang.oss-cn-hangzhou.aliyuncs.com/images/2026/08/25/20260825T122813Z-9b0f5605b08c7989-a5cb72af.png)

## 图表出来以后先核对数字

图画出来只是中间结果。正式使用前，至少要核对总数、分组和时间范围。

可以从原表中挑一个月份和一条产品线，手动求和，再与汇总结果对照。

还要确认利润究竟是金额还是利润率，月份有没有遗漏，退货或取消订单是否计入销售额。

这些口径一旦不同，图表看起来依然完整，结论却会走偏。

如果结果需要调整，不用重做全部内容。直接指出要改的部分即可。

```text
请继续修改刚才的分析结果。

销售额中排除订单状态为已取消的记录，利润图按产品线分别绘制，并在图表下方补充统计口径。

保留原始汇总结果，另存一份修订版本。
```

这样能留下修改前后的结果，也方便检查统计口径改变以后，哪些数字随之发生了变化。

## 没有现成表格时先搜集数据

有些分析任务开始时没有 Excel，材料散落在网页、报告或多个公开来源中。这时可以先让 WorkBuddy 按主题和范围搜集信息，再整理成结构化数据。

范围要写得尽量明确，尤其是地区、时间、指标和来源要求。以 AI 办公工具的市场信息为例，可以这样写。

```text
请搜集近 1 年国内 AI 办公工具相关的公开市场信息。

重点整理用户规模、主要应用场景和代表产品。每条数据需要记录发布日期、统计口径、来源名称和原文链接。

优先使用企业官方公告、正式研究报告和权威媒体材料。不同来源的数据口径不一致时，请分别保留并加以说明，不要直接合并。

先生成结构化数据表，暂时不要写报告。
```

先要数据表，可以把搜集和写报告分开。

收到结果以后，先检查链接能否打开、发布日期是否符合范围、同名指标的统计口径是否一致。

有了可核对的数据，再让 WorkBuddy 生成报告。

```text
请根据已经整理的数据生成一份可视化分析报告，供管理层阅读。

报告包含核心发现、关键数据图表、趋势判断和行动建议。每张图表注明数据来源和时间范围，正文中的判断要能对应到已有数据。

来源不足或口径冲突的地方单独标记，不要给出确定结论。
```

这一步把报告读者、章节要求和引用规则写清楚。最终结果除了图表，还会有对应的解释和来源信息，后续做汇报时更方便核查。

## 交付前检查这几项

打开结果文件后，先确认图表标题、横轴、纵轴和单位是否完整。

再检查汇总数字能否回到原始数据，文字结论是否与图表一致。

使用公开数据时，还要检查来源链接、发布时间和统计口径。

某条数据只有二次转载，没有原始出处，就不适合直接放进重要结论。两个来源使用不同样本，也不要放在同一张图里硬做比较。

最后删掉没有回答问题的图表。管理层需要看到结论依据，项目成员还要知道异常落在哪些数据上。

根据读者保留必要的信息，报告会比堆满图形更容易使用。

## 写在最后

第一次练习时，可以选一张字段清楚、自己熟悉结果的销售表。

先让 WorkBuddy 检查字段，再做一次分组汇总和两张图，最后抽查一组数字。

这套过程跑通以后，再增加更多指标或改成公开数据搜集。

数据分析最怕口径没说清楚，图表却已经做完。

把问题、范围和核对方式提前写进任务，后面的修改会少很多。
