# 区域银行首次拜访作战包预览

合成画像：120家网点，科技部近两年重点是统一数据服务与客服质检；对方负责人关注“可控试点”和审计。由于客户名称未提供且未联网，所有背景均需现场确认。

| 痛点假设 | 依据状态 | 现场验证问题 |
|---|---|---|
| 客服知识分散 | 合成假设 | 同一政策更新要同步几个系统？ |
| 数据申请周期长 | 合成假设 | 从申请到可用通常经过哪些审批？ |
| AI试点难过审计 | 合成假设 | 当前最担心权限、日志还是责任？ |

## 三个破冰话题

1. 从“银行AI项目如何先过可控性门槛”切入，不夸产品；
2. 请教对方今年最想缩短的一个内部周期；
3. 分享一页同类项目的失败复盘，再问哪些像他们。

## 漏斗式问题

业务：哪个流程每周重复且结果可验收？
影响：目前耗时、错误和客户投诉各多少？
决策：谁拥有流程、数据和风险签字权？
预算：试点预算来自科技、业务还是创新专项？
时间：什么节点前必须看到可量化结果？

建议案例：知识更新可追溯、工单质检人工接管，均需用真实案例替换。

跟进邮件摘录：“感谢今天分享贵行在权限审计和知识更新上的实际约束。我们建议先用一个不触达生产写权限的4周试点验证，附件只记录双方确认的范围与指标。”正式作战包必须联网附真实来源URL，并把未确认假设清楚标注。
