# 第 3 章 ~/.workbuddy 全景：SQLite 管调度，文件管 Harness

第 1 章说过，这本书拆解的对象物理上是你的数据目录。现在正式开门。这一章的目标很实际：逛完 `~/.workbuddy`，给每个目录一个职责标签，让你之后任何时候想知道「某东西存在哪」，都能自己找到答案。

读完本章，你应能独立回答三个问题：WorkBuddy 在我电脑上存了哪些东西？哪些是配置、哪些是记录、哪些是敏感数据？为什么 Harness 资产几乎全是文件而不是数据库？

## 3.1 动手：三分钟逛完数据目录

打开终端，执行（全部只读）：

```
ls ~/.workbuddy/
```

你会看到四十多个条目。别慌，它们分六个家族。挨个看过去：

```
cat ~/.workbuddy/MEMORY.md
ls ~/.workbuddy/plugins/marketplaces/
ls ~/.workbuddy/skills/ | head
ls ~/.workbuddy/projects/
```

第一条读的是你的用户级长期记忆（内容可能只有寥寥几行，这正常，见第 4 章）；第二条列出插件市场（本机实测五个；你的机器装得少会更少）；第三条是你的技能库；第四条最有意思——projects 目录下的每个子目录名，就是你某个项目文件夹的绝对路径转写。找找看，你正在用的项目大概率躺在里面，装着你的全部会话记录。

## 3.2 六个家族

**家族一：身份与记忆。** `SOUL.md`（人格）、`IDENTITY.md`（身份卡）、`USER.md`（你的画像）、`MEMORY.md`（长期记忆）四个文件，加上 `memory/`（云端记忆的本地缓存）和 `memery/`（一个拼写独特的目录，第 13 章讲它的来历）。这是第 4、6 章的主场。

**家族二：扩展系统。** `plugins/`（插件本体与登记）、`skills/`（技能库）、`skills-marketplace/`（技能市场）、`connectors/` 与 `connectors-marketplace/`（连接器）、`extensions/`。判断「装了什么」看这里，第 7—9、11 章的主场。

**家族三：配置。** `settings.json`（总开关：插件启停、通道、沙箱白名单）、`mcp.json`（MCP 服务器）、`models.json`（模型端点，含密钥，敏感）。第 12 章会讲这些文件的安全属性。

**家族四：会话与证据。** `projects/`（按项目分组的会话 JSONL）、`traces/`（执行轨迹）、`audit-log/`（审计日志）、`file-history/`（文件改动快照）、`blobs/`（产物存储）、`artifact-index/`（产物索引）、`workspace/`（每会话工作区）。第 10 章的主场。

**家族五：调度。** `workbuddy.db`——唯一的 SQLite 数据库，外加 `tasks/`、`plans/`、`todos/`、`automations` 相关表。存的是定时任务、会话统计、工作空间登记这类「运行时要查询的状态」。

**家族六：运行时杂项。** `app/`（Electron 浏览器内核数据）、`binaries/`（自带的 node 与 python）、`logs/`、`shell-snapshots/`、缓存与迁移目录。出问题时 `logs/` 是第一现场。

## 3.3 关键判断：为什么 Harness 走文件，调度走数据库

实测 `workbuddy.db` 的表结构，只有八张表：automations（定时任务定义）、automation_runs（执行历史）、automation_runtime_state（下次执行时间）、automation_delivery_outbox（投递队列）、sessions、session_usage（用量统计）、workspaces、迁移元数据。**没有记忆表、没有插件表、没有提示词表**——Harness 资产一个都不进数据库。

这是一个值得停下来想的架构判断。提示词模板、身份文件、记忆、技能、插件清单全部用纯文本文件（Markdown、JSON、YAML）承载，好处至少有三个：用户可以直接看和改（这本书才可能存在）；生态格式可以直接复用（WorkBuddy 的技能格式与开发者工具一致，第 13 章）；版本更新按文件分发（插件市场把市场当 zip 包下载解压）。数据库只承载需要高频查询和事务的调度状态。**「文件是给人和生态的，数据库是给调度器的」**——记住这个分工，你就能预测任何新功能落在哪。

## 3.4 两个实用推论

推论一：**备份与迁移变得简单**。想让另一台电脑长成这台的样式，理论上拷贝身份四件套、settings.json、skills、plugins 目录即可（敏感凭证另说，第 12 章讲风险）。官方的跨设备同步走它自己的通道，但文件在那儿，主动权就在你手里。

推论二：**「不生效」排查有了物理路径**。改了身份文件没变化？看文件是否真被读（第 5 章的拼装清单）、有没有被缓存、版本是否已变（市场自动更新可能改掉你以为稳定的东西）。第 14 章把这套排查整理成五步法。

## 3.5 隐私视角：这个目录里躺着什么

冷静看一下：你的身份画像、长期记忆、全部会话记录（含你发过的每句话）、文件改动历史、使用统计，都在这一个目录里，明文为主。这是能力的代价。三个动作降低风险：敏感对话后清理对应会话文件（第 10 章教你定位）；理解 models.json 里第三方模型端点意味着对话可能离开腾讯基础设施（第 12 章）；备份这个目录时按敏感数据对待。更完整的清单在第 12 章。
