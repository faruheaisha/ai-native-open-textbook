# 第 13 章 生态坐标：同源、兼容与产品矩阵

拆到文件层的人难免起疑：WorkBuddy 的技能格式怎么和开发者工具一模一样？身份文件的名字 SOUL、IDENTITY 为什么在另一个开源项目里也有？数据目录里那个拼错一样的 `memery` 是怎么回事？

这些不是巧合。这一章把 WorkBuddy 放回它的生态坐标——它不是从零造的孤岛，而是腾讯一张多产品棋子网络上的节点。理解它的出身，你才能预测它的兼容性边界，也才理解前十二章里那些「异形」设计的来历。本章的证据密度低于机制章（公司战略层的公开材料有限），推断比例高，每处都标了来源属性，读的时候留意。

读完本章，你应能说出 WorkBuddy 与 CodeBuddy、OpenClaw 的关系，解释技能与身份格式的跨产品兼容，并把 WorkBuddy 放进腾讯 AI 产品矩阵的正确位置。

## 13.1 出身：从代码助手到通用助手

时间线（据媒体访谈与公开报道整理）：2022 年，腾讯投入 AI Coding；2024 年 5 月，开发者工具 CodeBuddy 发布；2025 年，CodeBuddy 相继推出 IDE 形态与终端形态，内部覆盖上万名工程师，部分项目 AI 生成代码占比达九成；2026 年 1 月，Claude Cowork 的出现提供了「通用 Agent 桌面端」的外部验证；同月一个周末，团队用 48 小时基于 CodeBuddy 做出了 WorkBuddy 0.01 原型内测；3 月 9 日正式公测；到 6 月，第三方统计月活两千万、日活一千三百万量级（报道标题口径为 1200 万），桌面端用户占比超过九成。

这条时间线解释了本书反复出现的现象：**WorkBuddy 的骨架是一个成熟的开发者 Agent harness，外面套了一层面向普通人的 UI**。48 小时能出原型，正因为最难的部分（工具调用、沙箱、会话管理、提示词工程）在 CodeBuddy 里已经打磨了两年。你在第 5 章看到的模板体系、第 8 章看到的插件格式、第 9 章看到的 SKILL.md 规范，都是这条血脉的延续。媒体访谈里团队负责人的原话「让写代码像写文档一样简单」，在 WorkBuddy 上完成了一次倒转——让 Agent 的工程底座去服务写文档的人。

## 13.2 文件级的亲缘证据

血缘不该只听故事，看文件。本机实测的三组硬证据：

**插件清单格式 `.codebuddy-plugin`**。WorkBuddy 五个市场里的每个插件（包括专家、包括 WorkBuddy 自己的内置包）都用这个目录名放清单。格式是 CodeBuddy 定义的，连开发者官方市场的名字都叫 codebuddy-plugins-official。

**技能市场格式 `.codebuddy-skill`**。技能市场的清单目录同名同构，分发走同一个下载域名。

**身份四件套与 OpenClaw 生态**。SOUL.md、IDENTITY.md、USER.md、MEMORY.md 这组约定，来自腾讯体系内另一条开源产品线（社区通称 OpenClaw 系，自托管的 Agent 网关项目）。数据目录里的 `memery/` 目录（那个独特拼写）、微信通道配置节（claw）、通道状态目录，都是同一生态的组件痕迹。本机的身份文件甚至自述「运行在 OpenClaw 上，也运行在 WorkBuddy 上」——**同一套人格文件，跨产品迁移使用**。

需要谨慎表述的部分：OpenClaw 与 WorkBuddy 的底层代码关系，公开口径是「兼容生态、各自实现」（媒体报道称 WorkBuddy 纯自研闭源，与开源项目代码无关；另有报道称公司内部曾有基于 OpenClaw 的并行项目，其团队与入口后来并入了 WorkBuddy 体系）。本书采取的立场：**格式兼容是文件级事实，代码关系不做断言**。对你的实际意义很具体：你为 OpenClaw 生态找的人格文件、技能，大概率能在 WorkBuddy 里直接用；反之亦然。

## 13.3 产品矩阵中的位置

把镜头拉远。腾讯当前面向用户的 AI 助手矩阵里，各产品的分工大致是：元宝（通用对话助手，移动为主）、ima.copilot（腾讯的知识库型助手产品）、CodeBuddy（开发者工具）、WorkBuddy（桌面通用 Agent，办公与专业场景）。已取证的媒体信号（36 氪访谈，2026 年中）显示 WorkBuddy 在腾讯内部的优先级显著上调——团队正在冲刺公司级「名品堂」荣誉（微信支付、王者荣耀曾获此级认可）。企业版在年中产业大会上发布，带托管 Agent、检查点恢复、集中审计能力，走的是组织市场。

这个位置解释了本书读者关心的一个趋势判断：WorkBuddy 的 Harness 会持续向「组织可管理」方向加码（版本迭代里权限、审计、企业集成的条目密度可见地上升），同时借 CodeBuddy 生态持续获得开发者侧的能力输送（插件、技能的供给侧）。**个人用户得到生态红利，组织用户得到治理能力，两条线的汇合点是那套兼容格式**。

## 13.4 对使用者的三个推论

推论一：**技能与插件的供给会比单一产品的生态大得多**。为 CodeBuddy 写的工具、OpenClaw 社区的人格与技能，都是 WorkBuddy 的潜在弹药。找扩展时别只在 WorkBuddy 的商店里搜。

推论二：**格式稳定性高于产品稳定性**。产品每两天一版，但 `.codebuddy-plugin` 清单、SKILL.md frontmatter、身份四件套这些跨产品格式，变动的机会成本高得多。你沉淀在这几层的资产（技能、人格、规则）比任何具体版本的设置更长寿。

推论三：**多 Agent 的资产可移植窗口已经存在**。身份文件跨宿主、技能跨产品、插件跨兄弟品牌——今天在 WorkBuddy 里建立的资产，明天迁移到同生态任何产品的摩擦都很低。选型时这值得计入：买的不只是这个产品，是这张网络。

## 13.5 边界

本章边界最全书最宽，如实标注：出身时间线与战略信号来自媒体访谈与报道（已正文取证的来源为基础，未取证的传闻不收）；「同源底座」是格式证据加多方报道的推断，官方未发布架构声明；OpenClaw 的代码关系明确不做断言；产品矩阵分工为公开信息的综合归纳，非官方路线图。
