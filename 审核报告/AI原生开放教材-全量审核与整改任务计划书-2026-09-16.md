**审核立场：** 本轮只审核、取证和制定任务计划，不修改课程正文、构建脚本或网站实现  
**核心验收口径：** 外部课程正文原封不动接入；保留课程自身导航栏或目录顺序；本地教育/演示语料与公开网站的发布边界清晰；最终形成统一网站与蓝皮书 PDF 合集

## 一、审核结论

### 1.1 总体结论

**当前版本不予验收，不应标记为“全量原文接入完成”，也不应直接作为公开版蓝皮书或正式网站发布。**

本次审核确认：项目已经完成了大规模抓取、目录生成、页面编排和网站外壳建设，收录规模很大，但当前实现的基本范式仍是“把上游材料转换成适合 VitePress 的派生页面”，而不是“保存并展示不可变的上游课程原件”。这两个目标并不等价。

主要阻断点如下：

1. 构建器主动删除、改写、拆分或跳过上游内容，无法满足“正文原封不动”。
2. 课程原始导航并未全量保留，部分已导入导航还存在标题和路径错误。
3. 30 个标记为“仅引用”的来源被构建器强制搬入全文，与项目公开声明和公开发布边界冲突。
4. 页面“原文”按钮普遍指向课程入口文件，而非当前页面对应的上游文件，无法逐页核验。
5. 发布检查发现 29 篇 HTML 结构异常，但检查脚本仍返回成功；另有 69 类、224 处失效路径未进入正式门禁。
6. 124 个声明锚定 commit 的仓库来源中，只有 4 份本地快照保留 `.git` 证据；缺少全文件哈希清单，无法证明其余快照与所声明 commit 一致。
7. 当前仅形成 8 条学习路径，尚无可交付 PDF；与“所有卷册 + 蓝皮书合集 + 统一网站”的最终目标仍有明显缺口。

### 1.2 风险等级

**总体风险：R3（公开发布、第三方版权边界、海量内容完整性与不可逆传播风险）。**

当前的合入条件未同时满足：

`意图一致 ∧ 证据充分 ∧ 内容完整 ∧ 发布安全 ∧ 可维护 ∧ 可恢复 ∧ 可追责`

因此，即使页面数量很大、局部页面可打开、生产构建最终能够完成，也不能替代内容完整性、目录一致性与许可边界的验收。

## 三、详细发现

## F-01：许可和发布边界被构建器绕过

**等级：P0｜置信度：高｜状态：阻断公开发布**

### 证据

- `scripts/build-site-content.mjs:2134-2140` 对目录内所有来源直接 `return true`，注释明确表示把过去“仅引用”的官方文档整篇搬入。
- `README.md:100-104` 和 `NOTICE.md:9-15` 明确声明：“仅引用”不收录正文，只登记来源和原文入口。
- `site/docs/method/index.md:24-26` 同样声明“仅引用者只提供外链与索引”。
- 实际已生成完整正文，例如 `site/docs/lib/01-foundations/openai-api-docs-en/api-docs-guides-agents.md`，其页面元数据仍标记 `licenseLabel: "仅引用"`。
- 项目关于页指向公开 GitHub 仓库，站点配置也包含正式部署配置，因此当前实现不是单纯离线私有语料库。

### 影响

- 本地教育演示语料与公开网站内容混为同一构建目标。
- 公开声明与实际发布行为相反，权利人响应机制不能替代事前发布边界。
- 一次正常构建即可把全部“仅引用”正文带入公开产物。

### 最小修复

1. 建立两个明确目标：`local-full`（仅本地、不得发布）和 `public-site`（严格按发布许可过滤）。
2. 恢复以 `publishable`/许可策略为准的失败关闭逻辑；禁止以“教育用途”注释直接覆盖许可分类。
3. 在 CI 中检查：任何 `licenseLabel=仅引用` 的正文进入公开产物都必须失败。
4. 对非标准许可和未声明许可来源，取得明确授权或只保留外链，不以本报告替代法律意见。

### 验证方法

- 公开构建产物中，“仅引用”来源正文数必须为 0。
- 本地全量构建必须带醒目标识、独立输出目录，并确保部署脚本无法读取。
- README、NOTICE、网站关于页与实际构建统计完全一致。

## F-02：正文经过删除、改写、拆分和跳过，不满足“原封不动”

**等级：P1｜置信度：高｜状态：阻断内容验收**

### 证据

- 代表性实证：
  - 原文件 `upstream/08-agents/microsoft-ai-agents-for-beginners/01-intro-to-ai-agents/README.md:1-3` 包含视频缩略图和“点击图片观看视频”的提示。
  - 生成页 `site/docs/lib/08-agents/microsoft-ai-agents-for-beginners/01-intro-to-ai-agents.md:15-21` 从标题和欢迎语开始，上述教学媒体和提示已消失。

### 影响

- 课程案例、视频、互动组件、注释说明、元数据和大文档可能缺失。
- 页面“意思差不多”也不能满足用户要求的“课程本身原封不动”。
- 后续无法区分“上游原件”和“本站加工稿”，也无法对权利、引用和质量问题精确追溯。

### 最小修复

1. 把不可变原件层与展示层分离：原件只读保存，展示包装不得回写或覆盖原件。
2. 每个源文件保留原路径、原文件名、原字节、原 frontmatter、原媒体引用。
3. 网站需要兼容时，在外围适配；不得通过删除正文来换取构建成功。
4. 必须转换的格式建立显式“派生版”，并与“原文版”并列，不得继续宣称逐字一致。
5. 超大文件不能静默跳过；应原样下载、单独查看或明确阻断该课程验收。

### 验证方法

- 为每个上游文件生成 SHA-256；镜像原件哈希必须一致。
- 建立一对一文件清单：源路径、目标路径、字节数、哈希、媒体依赖、转换状态。
- 除换行标准化等预先批准项目外，任何正文差异都必须使完整性检查失败。
- 对视频、图片、代码附件、Notebook 和链接做资源级完整性检查。

1. HTML 问题页数大于 0 时必须退出 1。
2. 把链接检查器移入受版本控制的正式脚本目录并加入 `docs:release`。

4. `ignoreDeadLinks` 只能在有等价、严格且可复现的替代检查时使用。
5. 图片转存失败必须成为结构化错误状态，不能把错误提示字符串伪装成 Markdown 图片路径。
6. 构建日志按页面记录解析异常，并汇总未知代码语言，避免数万条重复警告掩盖真正失败原因。

### 验证方法

- 人为制造一个坏标签和一个死链，CI 必须失败；修复后才恢复通过。
- 回退修复实现后，对应测试必须失败，证明测试 oracle 有效。
- 正式发布要求 HTML 问题页 0、站内死链 0、缺失资源 0。

**等级：P2｜置信度：高**

- `README.md:9-15` 写 112 门全文课程、2,169 篇正文。
- `NOTICE.md:15-19` 写 107 条全文、36 条仅登记。
- 当前目录统计是 113 条可全文、30 条仅引用。
- 最新正文生成过程报告 136 门上架课程、24,449 篇正文。
- `site/docs/method/index.md:30-31` 又使用 26,787 篇 Markdown 等另一套口径。

### 影响

- 用户无法知道“来源、课程、页面、Markdown、全文上架”分别代表什么。
- 审核、发布和进度判断会被不一致数字误导。

### 最小修复

- 定义唯一统计词典，由构建 manifest 自动生成 README、NOTICE 和网站数据。
- 禁止手工维护数量；每次构建对文档中的派生统计做一致性校验。

### 验证方法

- 同一 commit 下，README、NOTICE、网站和机器清单的同口径数字必须一致。

## F-09：来源标题与课程身份抽取质量不足

**等级：P2｜置信度：高**

### 证据

`catalog/catalog.json` 中存在明显把安装步骤或正文句子当课程标题的记录，例如：

- `catalog/catalog.json:746`：`Clone code`
- `catalog/catalog.json:794`：`Clone the code`
- `catalog/catalog.json:1230`：`1. Clone this repository`
- `catalog/catalog.json:3439`：`Code within the code,`

### 影响

- 课程库检索、蓝皮书目录、来源署名和导航卡片难以辨识。
- 自动排序和去重可能基于错误身份进行。

### 最小修复

- 课程级元数据必须人工核验：正式名称、作者/组织、版本、语言、课程类型、入口和许可。
- 自动抽取只能提供候选，不能直接成为发布值。

### 验证方法

- 143 条来源元数据逐条签字确认；禁止使用安装命令、按钮文案或普通句子作为标题。

## F-10：变更规模过大，缺少可审查的 Evidence Pack

**等级：P2｜置信度：高**

### 证据

- 当前工作区存在 14,136 个变更路径，其中 13,267 个为未跟踪文件。
- 原始资料、生成页面、导航、主题、验证脚本和说明文档混在同一批变化中。
- 未发现与本批变更一一对应的需求清单、预期课程清单、差异报告、失败列表和回滚说明。

### 影响

- 无法把生成噪音与逻辑变更分开审核。
- 一次合入后若发现课程缺页、许可错误或导航错误，难以定位责任提交和安全回滚。

### 最小修复

- 按“规则/工具 → 单一来源导入 → 单卷验收 → 网站汇总 → PDF”拆分提交。
- 每批附 Evidence Pack：输入 manifest、输出 manifest、完整性差异、导航差异、许可判定、自动测试、人工抽样和回滚点。

### 验证方法

- 任一批次都能独立回答：改了什么、为什么、输入是什么、输出是什么、如何证明、如何回退。

## 四、目标架构：从“转换站”改为“不可变课程库 + 多种展示”

建议后续统一采用以下四层：

1. **原件层 Raw Archive**  
   保存上游原文件、原目录、原媒体、原导航和版本证据；只读、不可加工。

2. **证据层 Manifest & Provenance**  
   保存来源、commit、许可、逐文件哈希、导航顺序、抓取时间和授权范围。

3. **编排层 Curriculum Overlay**  
   只保存本站自己的卷册归类、学习路径、导读和中文释义；不得覆盖原文。

4. **发布层 Website / PDF**  
   网站和 PDF 都读取同一份已验收 manifest；展示适配在外围完成，任何内容降级必须显式报告。

这套架构允许本站“重新编排”，但不会把重新编排误称为上游原课程，也不会为解决渲染问题而删除教学内容。

## 五、整改实施计划

## 阶段 0：冻结与保全（优先级 P0）

**目标：** 防止当前错误扩大到公开发布。

任务：

1. 暂停把当前全量产物标记为正式版。
2. 冻结当前工作区快照，记录 HEAD、文件数量和现有构建日志。
3. 区分“本地全量语料”和“公开可发布内容”，设置不同输出目录与部署权限。
4. 建立问题页、死链和导航失败清单，不再静默忽略。

完成标准：

- 公开部署不会包含“仅引用”正文。
- 当前证据和问题清单可恢复、可复核。

## 阶段 1：建立真源与完整性基线（优先级 P0/P1）

**目标：** 先证明拿到的是什么，再生成网站。

任务：

1. 为 143 条来源建立统一 source manifest。
2. 为 124 个仓库来源重新验证 commit/archive；为网站来源记录抓取快照和条款。
3. 生成逐文件 SHA-256、字节数、媒体依赖和原始相对路径。
4. 将所有本地编辑移出原件层。
5. 明确每个来源的公开发布策略和本地演示策略。

完成标准：

- 143/143 来源有完整来源证据。
- 原件层重复构建结果一致；任何漂移都能被发现。

## 阶段 2：恢复原课程目录（优先级 P1）

**目标：** 课程的标题、层级、顺序和链接与原作者设计一致。

任务：

1. 为 76 门课程型来源指定导航真源。
2. 修复微软课程等错误抽取结果。
3. 把代码样例、扩展阅读和仓库文件从主课程顺序中分离。
4. 导航解析失败时阻断该课程进入“完成”状态。

完成标准：

- 76/76 课程完成导航逐项核验。
- 不存在 `Link` 之类丢失标题，不存在导航目标串课或串语言。

## 阶段 3：重构内容呈现（优先级 P1）

**目标：** 原文不动，网站仍可稳定阅读。

任务：

1. 原件与页面包装分离。
2. 为 Markdown、MDX、Notebook、HTML、PDF、视频和附件分别定义无损呈现策略。
3. 删除“为了能构建而删除正文”的规则。
4. 对无法安全渲染的内容使用原文件查看、沙箱或下载，不静默删减。
5. 中文释义作为并行注释层，不插入或覆盖原文文件。

完成标准：

- 原件哈希 100% 保持。
- 网站页面可定位到对应原件；所有展示降级均可见、可追踪。

## 阶段 4：修复质量门禁（优先级 P1）

**目标：** 红灯必须真正阻止发布。

任务：

1. 修复 29 篇 HTML 问题页。
2. 分类并修复 69 类、224 处失效路径。
3. 所有检查器遇错非零退出。
4. 增加正文哈希、导航顺序、逐页来源、资源完整性和许可过滤测试。
5. 建立小型黄金样本，包括微软课程、含 MDX/视频课程、超大文档、多语言课程和仅引用来源。

完成标准：

- HTML 问题页 0。
- 站内死链 0，缺失资源 0。
- 生产构建退出码 0，并成功生成可检查的 `dist`；失败图片不得变成相对路径。
- 人为回退关键修复时测试必然失败。

## 阶段 5：逐来源、逐卷验收（优先级 P1）

**目标：** 不再用“全站大数”代替课程完成度。

每个来源的验收包必须包含：

- 来源与版本证明
- 许可/授权分类
- 原始文件清单和哈希
- 原导航与站内导航对照
- 缺失、增加、变换文件清单
- 图片、视频、代码和附件检查
- 页面原文链接检查
- 人工抽样记录和责任人

完成标准：

- 只有证据包完整的来源才能进入“已完成”。
- 卷册完成度按已验收来源计算，不按已生成页面数计算。

## 阶段 6：网站与蓝皮书统一交付（优先级 P1/P2）

**目标：** 同一内容基线生成统一网站和 PDF 合集。

任务：

1. 冻结最终卷册总表和每卷课程顺序。
2. 网站与 PDF 共用 source/curriculum manifest。
3. 生成每卷 PDF、合集索引和统一版权/来源页。
4. PDF 视觉与可用性检查：书签、目录、分页、字体、代码、图片、链接和可访问性。
5. 网站检查：桌面/移动端、搜索、侧栏、跨卷导航、来源追踪和下载入口。

完成标准：

- 网站、分卷 PDF 和合集三者课程清单及顺序一致。
- 公开版只含允许发布内容；本地演示版不会被部署。

## 七、执行注意事项

1. **不要再以页面数量作为首要完成指标。** 页面越多，若缺少一对一证据，风险只会放大。
2. **不要把渲染成功等同于原文完整。** 删除视频、HTML、frontmatter 后构建成功，恰恰可能意味着课程被破坏。
3. **不要把目录树当课程目录。** 文件系统顺序通常不是教学顺序。
4. **不要在原件层做翻译、修字、补标题或链接重写。** 这些只能存在于展示层或注释层。
5. **不要用“仅供学习”自动推导可公开全文转载。** 本地私有使用和互联网公开部署是两个发布边界。
6. **不要让检查器只打印不失败。** 任何阻断级问题必须体现为非零退出状态。
7. **不要一次提交数万文件并混入规则改动。** 规则与生成结果分批，来源逐门验收。
8. **不要手工维护统计数字。** 统一由验收 manifest 生成。
9. **不要让网站和 PDF 各有一套正文。** 两者必须共享同一内容与顺序真源。
10. **保留回滚能力。** 每门课程、每卷和每次公开发布都应有可单独撤回的边界。

## 十、最终验收定义（Definition of Done）

只有同时满足以下条件，项目才能宣称“全量课程已接入并形成蓝皮书合集”：

1. 所有纳入范围的来源都有版本、许可和逐文件证据。
2. 每门课程正文、媒体和附件均保留原件；任何派生变化均与原件分层。
3. 每门课程的标题、层级和目录顺序与上游真源一致。
4. 每个站内页面都能准确跳到对应上游文件和固定版本。
5. 公开版严格遵守发布清单；本地全量版与公开部署物理隔离。
6. HTML、链接、资源、导航和完整性检查全部为零问题，且会真实阻断发布。
7. 每门课程和每卷均有 Evidence Pack、责任人和回滚点。
8. 所有卷册完成，网站、分卷 PDF 和合集使用同一内容清单与顺序。
9. README、NOTICE、网站统计和实际产物完全一致。
10. 经过内容、工程、许可边界和 PDF 视觉四类独立验收。

在此之前，建议项目状态统一标记为：**“大规模导入与验证中（非正式发布版）”。**
