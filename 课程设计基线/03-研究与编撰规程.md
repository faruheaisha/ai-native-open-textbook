# 研究与编撰规程

## 一、总生产线

```text
DISCOVER
  ↓
QUARANTINE
  ↓
IDENTITY VERIFY
  ↓
SOURCE REVIEW
  ↓
LICENSE / RIGHTS
  ↓
FRESHNESS
  ↓
FULL CONTENT REVIEW
  ↓
DEDUP
  ↓
QUALITY ASSESSMENT
  ↓
CONCEPT / TASK MAPPING
  ↓
BUILD / CURATE / ADAPT / INDEX
  ↓
ASSET REVIEW
  ↓
CURRICULUM MAPPING
  ↓
EDITORIAL QA
  ↓
VISUAL QA
  ↓
PUBLISH
  ↓
MONITOR
```

README、Stars 和营销页面只用于发现，不能代替 Full Content Review。

## 二、发现机制

- Publisher Graph：从一个厂商扩展到模型、产品、API、GitHub、Academy、Blog 和官方媒体。
- Reference Graph：沿优秀课程、论文和文档的引用继续向外发现。
- Organization Mining：定期查看重点 GitHub 组织的 repo、release、issue、PR、discussion、example、skill 和 benchmark。
- Social / Case Mining：只作为真实任务和案例候选来源。
- Community Nomination：允许外部提交，但必须经过同一套审核。

任何用户给出的产品名都只是搜索种子，不是研究边界。

## 三、知识处理

### 知识成熟度

- `Fundamental`：长期基础知识。
- `Established`：已广泛用于工程实践。
- `Developing`：快速发展但已有稳定价值。
- `Emerging`：新兴术语或方法。
- `Frontier`：研究前沿。
- `Hype / Unclear`：暂不进入正式课程。

### 知识呈现状态

- `Established Knowledge`：多个高质量独立来源基本一致，可形成统一正文。
- `Source Model / School`：某机构的一套解释框架，保留来源并列。
- `Emerging Interpretation`：明确标注并讨论，不下过早结论。

### 综合等级

- `C0`：原始资料推荐。
- `C1`：多来源并列。
- `C2`：对照分析。
- `C3`：证据充分后的教材综合模型。

不能为了目录整齐把所有主题直接升到 C3。

## 四、章节研究闸门

正式写作前必须先完成 `Chapter Evidence Packet`，至少包含：

- Canonical terminology
- Primary sources
- Official documentation / code / release
- Papers / standards
- Existing high-quality courses / pedagogical models
- Source definitions and context
- Architectures / patterns
- Areas of agreement
- Areas of divergence
- Real cases and failure cases
- Images / GIFs / videos / artifacts
- Workflows / skills / code / benchmark
- License / provenance / freshness
- Editorial decision：并列、比较、综合或暂缓

证据不充分时，只允许 C0–C2，不允许伪造统一答案。

## 五、课程设计方法

采用 Backward Design：

1. `Learning Outcome`：完成本课后能够做什么。
2. `Evidence of Learning`：用什么可观察结果证明学会。
3. `Learning Experience`：为得到该结果需要哪些概念、案例、步骤和练习。

采用 Spiral Curriculum：同一概念按初学使用、领域应用、开发实现、工程深入逐层展开，不在第一次出现时讲完全部细节。

## 六、标准章节形态

```text
Concept
→ Why it exists
→ Mechanism
→ Canonical Exemplar
→ Getting Ready / Configuration
→ Real Case
→ Artifact / Workflow
→ Failure Modes
→ Comparative Implementations
→ Generalization
→ Current Frontier
→ Primary Sources
```

面向零代码用户的实战课可以把结果预览和短 Demo 前置，但不应牺牲知识准确性。

## 七、案例证据等级

| EVL | 含义 | 课程使用 |
|---|---|---|
| EVL-0 | 未验证线索 | 不进入正文 |
| EVL-1 | 普通社区证据 | 仅补充或待核验 |
| EVL-2 | 高可信开源社区/精选证据 | 可进入课程 |
| EVL-3 | 官方完整演示 | 可进入课程，营销效果需标注 |
| EVL-4 | 多个独立可信来源确认 | 强证据 |
| EVL-5 | 团队独立复现 | 金标准案例 |
| EVL-6 | 多位学习者课堂验证 | 最高教学证据 |

未复现但可发布的案例记录 `Reproduction Debt`，包含当前等级、目标等级、优先级和原因。核心实验、公平对比、安全/隐私、高权限操作和来源互相矛盾的内容优先复现。

## 八、媒体与资产

每个媒体只承担一个教学任务：

- Screenshot：一个状态。
- GIF：一个动作及可见反馈，建议 3–15 秒。
- Diagram：一个 mental model。
- Video：一个完整过程。
- Artifact：最终结果和可检查证据。

素材来源优先级：团队复现、官方文档、官方 Blog/Academy、官方媒体、高质量 OSS 社区、真实用户案例、二手转载。优先级不等于自动授权，权利状态单独判断。

外部社交内容默认 `Index, not Mirror`。保存标题、作者、URL、日期、摘要、Claim、案例结构和权利状态；无授权不镜像全文和媒体。

## 九、资源质量门槛

Hard Gate：来源不明、盗版、严重过时、危险代码、虚假营销、明显错误、作者无法确认、许可证不允许，不能进入主库。

通过 Hard Gate 后再评估：Authority、Freshness、Educational Value、Reproducibility、Original Value、Maintenance、Presentation。

## 十、动态事实与更新

不同内容采用不同复核节奏：

- Benchmark、福利与促销：天级到周级。
- 价格、产品能力、套餐：周级到月级。
- CLI/API/依赖：Release trigger。
- 教程：月级到季度级。
- 基础概念：半年到年度。

Freshness 分开记录：concept、workflow、code/API、UI/assets、pricing。按钮位置变化不应让仍然有效的概念课整体失效。

## 十一、最小数据骨架

建议长期对象：Publisher、Source、Snapshot、Claim、Concept、ProductCapability、Task、Implementation、Case、Asset、Lesson、Course、Track、LiveFact。

关系主链：

```text
Publisher → Source → Claim → Concept → Task → Implementation
→ Case → Asset → Lesson → Course → Track
```

课程不是从链接直接生成；每一步都保留来源和决策。

## 十二、双载体发布

教材正文只在 Canonical Content Corpus 中维护，网站与 PDF 都是构建产物：

```text
Evidence / Claims / Cases / Assets
               ↓
       Publishable Chapter
          ┌────┴────┐
       Web Build   PDF Build
          ↓          ↓
       Living       Editioned
```

- 网站构建保留搜索、交互、动态事实、媒体、证据展开与更新日志。
- PDF 构建把交互转为关键帧、轨迹表、摘要和持久链接，冻结证据截止日。
- 网站正文和 PDF 正文发生差异时，必须回到内容真源修正，不允许分别维护补丁。
- 网站可以持续更新；已经发布的 PDF 不静默替换，只发布新版本和在线勘误。
- 每次构建记录 source commit、内容版本、证据截止日、资产清单和构建日志。

详细产品规范见 `05-网站与蓝皮书双载体出版范式.md`；可发布正文使用 `templates/Publishable-Chapter.md`。
