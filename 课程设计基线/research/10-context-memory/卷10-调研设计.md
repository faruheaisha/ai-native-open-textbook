## 一、Volume Contract

### 本卷承诺

读者完成本卷后，能解释指令层级、持续目标、计划、规格、上下文、记忆、压缩、状态与长期执行的完整体系；能区分 Instruction Hierarchy（Organization/User-global/Project/Directory/Task/Runtime）与 Context（Current/Project/Global/Retrieved/Tool/External）；能区分 Memory 的多个来源（人工指令、Agent 记忆、会话历史、检索知识、项目事实、用户记忆）；能解释 Compact、Resume/Fork/Checkpoint/Session/Branch 与跨小时/天任务的恢复与验证；能梳理 Extensions 谱系（Prompt、Project Instructions、Slash Commands、Skills、Tools、MCP、Plugins、Connectors、Hooks、Subagents）。

- 不深讲 Harness 产品本身（卷 09）。

- 不把 MCP/Skills 写成协议规范文档；讲它们在能力体系中的位置与使用判据。
- 不承诺产品配置细节稳定；配置进入 Live Facts。

## 十一、2026-09-10 第三批检索补充（Skill 成为独立品类）

### 11.1 定义必须重写

本卷原有的「Skill = 提示词模板」定义**作废**。Skill 现在是：

> **目录 + `SKILL.md` 协议 + 渐进式加载 + 可分发的能力包。**

**SKILL.md 规范要点**（来自 `libukai/awesome-agent-skills` README 的社区一致表述，**待回协议发布方核验**）：

- 一个 Skill = 一个目录，根目录必须有 `SKILL.md`
- frontmatter 必填 `name`、`description`；可选 `license`、`compatibility`、`metadata`、实验性 `allowed-tools`
- `name` ≤64 字符、只允许小写字母 / 数字 / 连字符、**必须与父目录同名**
- 可选子目录：`scripts/`、`references/`、`assets/`；在 `SKILL.md` 中以**相对 Skill 根目录**的路径引用
- 使用分**三阶段**：发现（discovery）→ 加载（loading）→ 执行（execution）

**教学含义**：Skill 的关键设计点是**按需加载**，不是把所有内容塞进系统提示。这与本卷的上下文工程主线（预算 / 压缩 / 分层加载）**直接咬合** —— Skill 与 Context Engineering 不是两个话题，而是同一问题的两面。
