## 逐条要点

### 1. deusyu/harness-engineering（5,874★，MIT）

- **定位**：一个"从阅读原文 → 拆解概念 → 形成思考 → 动手实践 → 输出作品"的完整学习档案，是本批中**方法论最完整**的中文来源。
- **结构（快照实读）**：
  - `concepts/` 00–07 共 8 篇：overview、repo-as-source-of-truth、mechanical-enforcement、entropy-and-garbage-collection、agent-readability、throughput-changes-merge、harness-definition、spec-as-product
  - `thinking/` 十余篇随笔（含 `subagent-is-child-runtime`、`guides-sensors-meets-claude-code-harness`、`harnessability-and-java`、`meta-harness-tensions`）
  - `practice/01-ralph-demo/`（含 `ralph.yml`、`PROMPT.md`、可运行 `wc.py` + `test_wc.py`）
  - `works/` 47 篇译文/原创（Fowler 备忘录与全文、Anthropic 多篇工程文、arXiv 论文、LangChain ADLC、METR uplift 等）
  - `references/articles.md`、`tools/`、`.claude/skills/curate-research/SKILL.md`
- **可借鉴的文档工程纪律**（本批最有价值的方法）：`references/articles.md` 自标为**计数唯一权威源**，规定"一篇文章 = 一个 `### N. {标题}` 编号小节"，并把根 README 徽章、去重清单、概览表全部显式声明为**下游冗余缓存**，要求"新增/删除文章时必须同一次提交更新本文 + 所有下游缓存"。→ 与本项目 `_快照索引.json` + 台账的分工同构，可作为**上游佐证**写进本项目的方法论章节。
- **风险**：79 篇是**它自己的计数口径**；译文属二次加工，引用外文原意时应回原文。

### 2. ZhangHanDong/harness-engineering-from-cc-to-ai-coding（1,500★，MIT）《马书》

- **定位**：以 Claude Code `v2.1.88` 公开发布包 + source map 还原结果为分析材料的**逆向工程式技术书**。这正是"harness engineering"从工程实现角度被讨论的最典型样本。
- **结构**：7 篇 + 4 附录 —— 第一篇 架构 / 第二篇 提示工程 / 第三篇 上下文管理 / 第四篇 提示词缓存 / 第五篇 安全与权限 / 第六篇 高级子系统 / 第七篇 AI Agent 构建者的经验教训。
- **边界声明（值得本项目抄写的写法）**："本书基于公开发布包与 source map 的逆向分析，仅用于技术研究与工程讨论；书中内容聚焦工程实现与设计模式，**不代表 Anthropic 官方立场**。"
- **风险（重要）**：内容依赖**特定版本**（`v2.1.88`）的还原结果，产品迭代后失效。引用任何机制细节都必须标注版本号与还原方法。
- **映射**：卷 09 主；卷 10（上下文管理、提示词缓存）；卷 12（安全与权限）。
