## 0. 这份文档解决什么

用户诉求原文：**"最后我希望能够做网页交互版的课程，就像 doubaowork.homes 之类的一样，方便学习者能够更好的学习，而且网页版交互设计的更加成熟和完善，视觉呈现和案例展示更是更加适配。"**

## 1. 两个对标站点的实现级解剖

两个站点都公开了完整仓库与 MIT 许可，因此**解剖到实现细节**而不是停留在观感。

### 1.1 样本 C：豆包工作蓝皮书 —— 纯静态 SPA + 生成式数据层

**技术形态**：无框架、无构建依赖的纯静态站点。`python3 -m http.server` 即可本地运行。

```text
site/
  index.html            # 入口 + 全局导航骨架
  css/  base.css · layout.css · article.css      # 视觉系统 / 布局 / 正文，三层分离
  js/   app.js（路由、搜索、按需加载、交互）· markdown.js（安全渲染）
  content/
    site-content.json   # 466 KB，58 节点全文
    site-index.json     # 38 KB，由全文生成的轻量首屏索引
  media/                # 公开图片与视频
  assets/               # 界面素材（品牌、二维码、作者名片、OG 图）
  _headers              # Cloudflare Pages 缓存策略
```

**关键设计一：内容与入口索引分层。** `site-index.json` 是构建期从 `site-content.json` 生成的精简索引，每个节点带**结构化指标**：

```json
{ "nodeToken": "doc-…", "parentToken": "doc-…", "title": "定时任务怎么建，才能稳定产出结果",
  "hasChild": false, "depth": 2, "order": 9,
  "imageCount": 5, "videoCount": 0, "charCount": 752,
  "excerpt": "定时任务最适合重复、规则稳定、结果好验收的工作。…" }
```

这让首屏**不必加载 466 KB 全文**，却能立刻渲染目录树、字数、媒体数量、摘要和搜索结果。构建期还有 `npm run build:index` 保证两者一致。

**关键设计二：三层分离 + 稳定阅读架构。** README 明确："内容数据、媒体资源与界面逻辑分层维护"。扩充章节时阅读架构不变。

**关键设计三：成熟的交互细节清单**（README「网站能力」原文）：

| 能力 | 实现要点 |
|---|---|
| 独立章节页 + 前后篇导航 + 页内目录 | hash 路由 `#/p/<nodeToken>` |
| 全文搜索 + **场景任务速达** | 搜索弹窗 + 任务入口并列，两条进入路径 |
| 图片画廊、组合排版、本地视频播放 | 媒体在正文内完成教学，不作装饰 |
| **阅读进度、继续阅读位置、目录展开偏好保存** | 写入 localStorage |
| 三种主题状态 | `system` / `light` / `dark`，inline 脚本在首帧前定主题 |
| 分享卡片、图片放大、**提示词一键复制** | 面向"照着做"的读者 |
| 移动端适配 | 响应式 |

**关键设计四：防闪白与可访问性。** `<head>` 内联脚本在渲染前读取 `localStorage` 写入 `document.documentElement.dataset.theme`，并同步 `meta[theme-color]`；`body.is-booting { visibility: hidden }` 防止未就绪闪烁。全站含 `skip-link`（跳到正文）、`role="dialog" aria-modal`、`role="combobox"` + `aria-autocomplete`、`aria-live` 提示。

**关键设计五：真实的质量门禁。** 仓库带浏览器回归测试与审计脚本，覆盖：启动、首页跳转、继续阅读、搜索、移动端、交流群、主题切换、首页配色；以及**全部内容路由、媒体文件存在性、控制台错误、横向溢出、正文图框、按需加载、模拟弱网首屏时间**。

**关键设计六：素材来源纪律。** `ASSET-PROVENANCE.md` 逐项记录品牌标志、二维码、作者名片、OG 图的来源、处理脚本、尺寸与 SHA-256，并明确"品牌标志版权归字节跳动所有，仅作内容展示与开发参考"；对**无法核验来源的作者名片，明确写"不补写无法核验的来源"**。

### 1.2 样本 D：WorkBuddy 蓝皮书 —— SSG + 编辑型视觉系统

**技术形态**：VitePress（`cleanUrls` + 本地搜索 + `lastUpdated` + sitemap + Mermaid + 按页 SEO）。

**关键设计一：侧边栏结构即课程结构。** `sidebar.ts` 把 27 章分成 4 篇 + 附录，全部 `collapsed: false`（默认全展开，读者一眼看到全貌）。

**关键设计二：案例侧边栏从内容自动生成。** 读取 `cases/submissions/*/index.md` 的 frontmatter，取 `title` 与 `date`，**按日期排序**生成侧边栏条目。新增案例只需加目录，不改配置。

**关键设计三：案例页用不同的阅读版式。** 配置里对 `cases/*` 统一设置 `aside: false, outline: false` —— 案例页取消右侧目录、放宽版心，因为案例是"照着做"而非"查资料"。

**关键设计四：公共文档 + 完整 UI 重设计方案。** 仓库内 `docs/plans/2026-07-10-workbuddy-pixel-green-ui-design.md` 是一份**可直接执行的设计规范**，含方向取舍、Design Token、字体尺度、动效、响应式断点、无障碍底线、实施映射与验收清单。

**关键设计五：首页的十段式信息架构**（实测抓取）：

```text
1  Hero            OPEN-SOURCE · 27 CHAPTERS · 2026  → 系列名 → 价值主张 → 双 CTA → 统计条
2  价值条          真实任务 / 可复现 / 社区共创 / 系统沉淀
3  实时统计        今日访问 · 今日浏览 · 累计访问 · 累计浏览
4  阅读路径        READING PATH / 01—04，四张路径卡（PART 01 · CH. 01—10 + 标题 + 描述 + 标签）
5  按任务进入      START WITH A REAL TASK，6 个任务入口卡
6  方法路径        FROM TASK TO TEAM，TASK → CASE → WORKFLOW → AI TEAM 四步
7  共创 CTA        黑底大字 + 双按钮
8  页脚
```

**关键设计六：视觉系统的"10–15%"原则。** 设计文档明确：像素元素只占整页 10%–15%；中文标题与正文坚持现代无衬线，像素字体只用于英文标签、数字、状态码；荧光绿不承担白底小字号正文；同一屏最多一个大面积品牌色区域。

### 1.3 两站对照

| 维度 | 样本 C 豆包蓝皮书 | 样本 D WorkBuddy | 本项目取向 |
|---|---|---|---|
| 技术 | 纯静态 SPA（无框架） | VitePress（SSG） | **SSG + 少量自定义组件**（§3.2） |
| 数据层 | 双层 JSON（全文 + 生成式索引） | Markdown + 构建期提取 | **Markdown 真源 + 构建期生成索引**（§3.3） |
| 搜索 | 自建（含摘要与计数） | VitePress Local Search | 自建索引 + 本地搜索 |
| 进入路径 | 顺序（目录）+ 任务速达 | 顺序（阅读路径）+ 任务入口 | **四条学习路径 + 按任务进入**（§5） |
| 案例 | 场景任务速达 | 独立案例集 + 宽版式 | **独立案例层 + 回放**（§7） |
| 视觉 | 品牌蓝白，克制 | 荧光绿像素，编辑型 | **内容寿命三色为品牌信号**（§9） |
| 深色模式 | system/light/dark 三态 | light/dark | 三态 |
| 无障碍 | skip link + ARIA 完整 | 设计文档列出底线 | 两者并集（§11） |
| 质量门禁 | 浏览器回归 + audit 脚本 | 构建 + 人工截图验收 | 两者并集（§13） |
| 素材纪律 | `ASSET-PROVENANCE.md` + 哈希 | 许可证来源要求 | 沿用本项目 Source Record 体系（§12.3） |

**结论**：样本 C 的**工程严谨度**更高（数据分层、防闪白、回归测试、素材溯源）；样本 D 的**产品与视觉完整度**更高（首页信息架构、设计规范、案例版式、公开 UI 方案）。本项目需要**两者的并集**，再加上两站都没有的两件事：**证据层交互**与**案例回放**。

## 3. 产品定位与技术选型

### 3.1 站点在三个载体中的职责

沿用 `05-网站与蓝皮书双载体出版范式.md`，这里只补充**交互层**的分工：

```text
网站独有（PDF 必须降级但不可缺失的信息）
├─ 从角色 / 任务 / 概念 / 产品四个入口进入同一图谱
├─ 案例回放：trace、工具调用、决策点、人工介入
├─ 证据面板：主张 → CEP → 来源 → 核验日期
├─ 可交互评测与练习提交
└─ 勘误与更新日志（实时）

PDF 独有
├─ 证据截止日的编辑判断（有开头、有路径、有结论、有边界）
├─ 离线与打印
└─ 正式引用与版本冻结

两者共有（同源生成，语义必须一致）
└─ 全部正文、概念定义、案例描述、验收标准
```

### 3.2 技术选型决定

| 候选 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| 纯静态 SPA（样本 C） | 零依赖、首屏可控、交互自由 | 无 SSG，SEO 与首屏内容需自行处理；14 卷规模下自建 Markdown 渲染管线成本高 | 部分吸收 |
| VitePress（样本 D） | SSG、本地搜索、侧边栏、深色模式、SEO 开箱即用；Markdown 真源 | 需要自定义组件时受 Vue 生态约束 | **采用** |
| 自建 SSG + 框架 | 完全自由 | 重复造轮子，违反课程宪法原则 7 | 不采用 |

**决定**：**以 VitePress 为骨架**（SSG + 本地搜索 + 侧边栏 + 深色模式 + 按页 SEO），**以自定义主题层和少量 Vue 组件承载本项目独有能力**（证据面板、案例回放、寿命标记、毕业产物展示）。

**理由**：

1. 与内容真源一致。`content/` 是 Markdown，VitePress 直接消费，不需要中间转换（课程宪法原则 17）。
2. 同语言、同题材已有验证案例（样本 D，MIT）。
3. 静态产物可离线、可镜像、可长期保存，符合"开放仓库"定位。
4. 需要自定义的地方全部落在**组件与样式层**，不动内容管线 —— 与样本 D 的"明确不改"清单一致。

**明确不做**：不做后端、不做登录、不做数据库、不做埋点、不引入重型动画库、不做客户端驱动的全文渲染。

### 3.3 数据层与目录结构

在 `05-…` 已定目录基础上补充站点层：

```text

  site-index.json            ← 站点索引（见下）
  claims.json                ← 主张 → CEP → 来源

  .vitepress/
    config.mts
    sidebar.ts               ← 由 data/site-index.json 生成，不手写
    theme/
      index.ts
      style.css              ← Design Token 全量
      components/
        EvidencePanel.vue    ← 证据面板
        CaseReplay.vue       ← 案例回放
        LifetimeTag.vue      ← 稳定 / 当前 / 前沿标记

  audit.mjs                  ← 链接 / 溢出 / 控制台 / 弱网首屏
```

## 4. 信息架构与路由

### 4.1 路由表


## 7. 案例展示设计（用户重点）

用户明确要求"案例展示更加适配"。两站的做法分别是"场景任务速达"（C）与"独立案例集 + 宽版式"（D）。本项目在此之上按编排规范 §9 的三类案例分层，并为每类设计不同的呈现。

### 7.1 三类案例，三种呈现

| 类型 | 呈现形态 | 版式 |
|---|---|---|
| **Spine Case（贯穿案例）** | 卷内主线，随章节生长；卷末汇总为毕业产物 | 章内嵌入 + 卷尾汇总页 |
| **Chapter Case（章内案例）** | 章内一节，最小可运行示例 | 章内标准版式 |
| **Case Atlas（案例库）** | 独立详情页 + 可过滤列表 | 宽版式（无右栏） |

### 7.2 案例卡片（列表与入口统一）

```text
┌─────────────────────────────────────────────┐
│ CASE-08-01                        EVL-1     │  ← 编号 + 证据等级徽标
│ 活动选择与日历写入                            │  ← 任务名
│ 从一个模糊请求，到可验证的日历写入             │  ← 一句话
│                                             │
│ 输入  自然语言请求 + 日历权限                 │
│ 产物  日程条目 + 运行 trace + 验收记录         │
│ 失败  3 类已记录  ·  时长 40 分钟  ·  难度 ▮▮▯ │
│                                             │
│ [看回放]  [下载产物]  [查看证据]              │  ← 三个动作
└─────────────────────────────────────────────┘
```

**证据等级徽标是必须项**：EVL-1（设计级）到 EVL-5（已复现）用**填充度**而非颜色区分，避免与寿命色冲突。

### 7.3 案例回放（Trace Replay）—— 本项目独有能力

这是"网站能做而纸面不能做"的核心，产品模型已承诺。

**时间轴 + 步骤轨道**：

```text
[▶ 播放] [⏮] [⏭]  速度 1×    步骤 3 / 12

时间轴  ━━━━●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        S1  S2  S3  S4        …            S12

当前步骤  S3 · 选择下一步
├─ 决策     调用工具 search_calendar
├─ 参数     { "date": "2026-09-11", "window": "14:00-18:00" }
├─ 观察     返回 3 个候选时段
├─ 状态变化 available_slots: 3 → 3，pending_write: false
└─ ⚠ 决策点  模型在此处选择了「先比较再写」，而不是直接写入

[标注]  🟡 人工介入  🔴 失败  🟢 验证通过
```

**五条设计规则**：

1. **逐步可控**，不用自动播放的连续动画（读者需要停下来看）。
2. 每一步显示**状态变化**，不只显示动作。
3. **决策点必须标出**：模型在哪些地方做了选择、选择空间是什么。
4. **失败与人工介入用轨道标注**，可一键跳到该步。
5. **PDF 降级**：关键帧截图 + 轨迹表 + 在线二维码（`05-…` 已规定）。

**实现约束**：回放数据以 JSON 存放（`assets/cases/<case-id>/trace.json`），组件只做渲染；不把 trace 硬编码进组件。

### 7.4 产物展示

- 产物清单化：每个产物显示**类型**（文件/表格/代码/图片/视频）、**大小**、**可下载**。
- 可预览的产物（Markdown、CSV、图片）做站内预览，不做无谓跳转。
- 不可分发的产物（第三方素材、含个人数据）**明确标注为不可下载并说明原因**。这一条是样本 C 的素材纪律的延伸。

### 7.5 案例库页

- 过滤维度：卷 / EVL / 难度 / 时长 / 任务类型。
- 默认排序按"证据等级降序 + 卷号"，**不按时间** —— 因为教材关注的是可复现性，不是新鲜度（与样本 D 按日期排序不同，需在页面上说明理由）。
- 每个案例卡可一键展开为对照表（输入 / 产物 / 失败 / 验收）。

## 8. 证据层交互（本项目独有能力）

两站的陈述都是同一置信度；本项目必须让读者**随时看到一句话的底气来自哪里**。这是差异化最集中的地方。

### 8.1 三处呈现

```text
1. 行内标记   正文中的关键主张后跟一个轻量标记 ▤
               点击 → 右侧展开证据卡片，不跳转、不打断阅读

2. 证据面板   章阅读页右上角「证据」按钮
               展开本章全部主张 → CEP → 来源 → 核验日期

3. 来源总表   /sources/ 全站可检索的来源与主张对照表
```

### 8.2 证据卡片字段

```text
主张      <一句话原文>
类型      Source Definition | Source View | Editorial Synthesis | Proposed Model
综合等级  C0 – C3
来源      SRC-… ×N（可展开看每条的定位与摘录）
核验日期  2026-09-08
适用版本  <产品/框架版本；无则 —>
分歧      <若来源间存在分歧，此处显式列出，不抹平>
```

**纪律**：分歧必须显示。课程宪法要求"对分歧与歧义进行展示、比较和解释，不偷偷消除"，因此证据卡片里必须有"分歧"字段——**这是两站都不可能有、我们必须有的**。

### 8.3 内容寿命标记

三种寿命在**目录、章标题、卡片、证据面板**四处一致显示：

| 标记 | 含义 | 视觉 |
|---|---|---|
| `STABLE` | 长期知识，进 PDF 正文 | 实心方块 |
| `CURRENT` | 产品实现与当前实践，带核验日期 | 半填充方块 |
| `FRONTIER` | 前沿快照，仅网站维护 | 空心方块 |

### 8.4 诚实降级入口

网站上必须能一眼看出**哪些内容还不够硬**。每个章/案例展示四项状态：

```text
证据  CEP 已完成 / CEP 排队中 / 无 CEP
复现  EVL-5 已复现 / EVL-1 设计级 / 未设计
许可  已核验 / 部分核验 / 未核验
审查  已审查 / 起草中
```

**禁止**用视觉手段（颜色、徽标）掩盖未完成状态。缺证据、缺复现、缺许可的内容必须在卡片和章页上显式标注，并链接到决策队列中的对应条目。

## 9. 视觉系统

### 9.1 定位

借鉴样本 D 的方法（先定方向再定 Token），但方向不同。

**方向：Editorial Research / 编辑型研究感。**

理由：本项目的读者是大学生、知识工作者、Builder 与工程师；内容是带证据的长期教材而非工具手册。视觉必须**先像一本可信的书，再像一个有性格的品牌**。样本 D 的像素科技感与样本 C 的品牌蓝都不完全适配。

### 9.2 色彩 Token

**浅色模式**

| 用途 | 色值 | 使用规则 |
|---|---|---|
| Ink | `#14161A` | 标题、主要按钮、深色区域背景 |
| Paper | `#F6F5F1` | 页面主背景（暖白，不用冷白灰） |
| Surface | `#FFFFFF` | 卡片、正文、搜索框 |
| Line | `#DCDAD3` | 分隔线、卡片边框、表格线 |
| Text Secondary | `#63666B` | 次级信息 |
| Accent | `#1B4DE4` | 主按钮、当前状态、链接 |
| Accent Soft | `#E8EDFC` | 浅强调底 |
| **Lifetime Stable** | `#2F7D4F` | 稳定核心标记 |
| **Lifetime Current** | `#B07714` | 当前实践标记 + 核验日期 |
| **Lifetime Frontier** | `#6B3FD4` | 前沿快照标记 |

**深色模式**

| 用途 | 色值 |
|---|---|
| Background | `#101216` |
| Surface | `#171A1F` |
| Surface Raised | `#1F232A` |
| Text Primary | `#F2F3F0` |
| Text Secondary | `#A8ADB5` |
| Line | `#2E333B` |
| Accent | `#6E8CFF` |
| Lifetime 三色 | 提亮一档，保持语义不变 |

**核心决策：内容寿命三色即品牌信号。** 这是本项目独有的视觉语言 —— 用同一套颜色在目录、章页、卡片、证据面板标记"这条知识有多稳"。它同时服务于教学（读者知道什么会过期）和品牌（一眼可辨）。

**禁止事项**：

- 不用渐变作为品牌色；不用玻璃拟态、彩色光晕、3D 球。
- 不用寿命三色做装饰；它们只表示寿命语义。
- 同一屏最多一个大面积 Accent 区域。
- 不用颜色单独承载状态（必须同时有文字或形状）。

### 9.3 字体与排版

- 中文标题：`PingFang SC / Microsoft YaHei / system-ui`，字重 700–800。
- 中文正文：系统无衬线，字重 400–500，行高 `1.8–1.9`。
- 英文与数字：`Inter`（本地托管，仅 latin 子集）。
- 等宽（证据 ID、CEP 编号、命令、trace）：`JetBrains Mono / ui-monospace`。

| 场景 | 桌面端 | 移动端 |
|---|---|---|
| 首页 H1 | 64–80px / 1.02 | 40–48px / 1.08 |
| 区块标题 | 36–44px | 28–34px |
| 章 H1 | 44–52px | 34–40px |
| 正文 | 17–18px | 16–17px |
| 等宽标签 | 13–14px | 12–13px |

**约束**：不使用像素字体（与样本 D 相反）。本项目的识别度来自寿命三色与结构线，不来自字体风格。

### 9.4 圆角、边框与阴影

- 卡片与容器：`8px`；按钮：`6px`（不使用胶囊）。
- 边框：`1px`，用 Line 色；重点容器可用 `1.5px` Ink。
- 阴影克制：仅悬停用 `0 1px 0` 硬边或 `0 2px 8px rgba(0,0,0,.06)`；不使用大模糊柔光。
- 正文图片：`8px` 圆角 + 1px 边框 + 小号图注。

### 9.5 结构线语言（替代样本 D 的像素图标）

本项目不使用插画或像素资产，改用**结构线与标记**建立识别度：

- 章节编号：等宽数字 + 左侧 3px 寿命色竖条。
- 卷册卡片：左上角等宽卷号 + 顶部 4px 寿命色条。
- 分段读法：三段用 `▮▮▮` 三格进度条表示，当前段实心。
- 证据标记：行内 `▤` 符号（可程序化渲染，无字体依赖）。
- 方法链：七个节点用等宽缩写 + 箭头连接。

所有结构线元素**不用外部素材**，全部由 CSS 与内联 SVG 生成 —— 从根本上回避素材许可问题。

## 10. 动效规范

动效必须短、稳、克制（沿用样本 D 的原则）。

| 场景 | 规范 |
|---|---|
| 首屏进入 | 标题、副标、按钮依次淡入并上移 8–12px，总时长 ≤ 500ms |
| 卡片悬停 | 上移 3px + 边框转 Ink，不做旋转与缩放 |
| 按钮悬停 | 硬阴影 0 → `0 2px 0`；按下回落 |
| 目录当前状态 | 颜色变化 150–180ms |
| 证据面板 | 右侧抽屉滑入 180ms，背景轻微变暗 |
| 回放步骤切换 | 内容交叉淡入 120ms，不做轨迹动画 |
| 寿命标记 | 无动效（语义标记不应吸引注意力） |

**禁止**：持续漂浮、自动跑马灯、鼠标跟随、视差滚动、大面积滚动触发动画、自动播放的回放动画。

**必须支持** `prefers-reduced-motion: reduce`，关闭全部非必要动画与过渡。

## 11. 响应式与无障碍

### 11.1 断点

| 宽度 | 布局 |
|---|---|
| ≥ 1440px | 内容最大宽度 1280px；三栏（侧栏 / 正文 / 目录）；Hero 两列 |
| 1200–1439px | 同上，边距收紧；Hero 保持两列 |
| 768–1199px | 右侧目录隐藏；左侧栏保留；Hero 上下布局 |
| < 768px | 单栏；侧边栏改抽屉；正文内边距 20–24px；Hero 单列 |

**重点测试宽度**：`1440 / 1024 / 768 / 390px`（沿用样本 D 的测试集）。

**移动端约束**：无横向滚动；按钮与图标触控区 ≥ 44px；表格允许横向滚动但不缩小字号；标题无单字孤行。

### 11.2 无障碍底线（两站并集，作为硬性验收）

- 正文文字与背景对比度 ≥ WCAG AA（4.5:1）；寿命三色不承担小字号正文。
- 全部交互元素有可见键盘 Focus：`3px` 双层焦点环（Ink + Accent）。
- `skip-link` 跳到正文。
- 导航、状态、寿命标记**不能只靠颜色**区分，必须同时有文字或形状。
- 搜索实现 `role="combobox"` + `aria-autocomplete` + `aria-expanded`；结果列表 `role="listbox"`；提示 `aria-live="polite"`。
- 证据面板与回放组件：`role="dialog" aria-modal="true"`，支持 Esc 关闭，焦点可返回。
- 图片必须有 `alt`；纯装饰元素 `aria-hidden="true"`。
- 支持 `prefers-reduced-motion`。
- 打印样式：证据面板与回放区自动降级为静态文本。

## 12. 性能、素材与纪律

### 12.1 性能预算

| 指标 | 目标 | 依据 |
|---|---|---|
| 首屏 HTML（上屏内容） | 静态预渲染，正文无需 JS | 样本 C 的分层索引思路 |
| 首页 JS（gzip） | ≤ 120 KB | — |
| 章页首次可读 | ≤ 1.5s（模拟弱网 Slow 3G） | 样本 C 的 audit 含弱网首屏 |
| 图片 | 懒加载 + 显式宽高（避免 CLS） | 样本 D 配置 `lazyLoading` |
| 字体 | 仅本地托管，仅 latin 子集，`preload` 关键字重 | 样本 C 做法 |
| 搜索索引 | 构建期生成，按需加载 | 样本 C + D |

**禁止**：首屏加载全文 JSON（14 卷规模下必然超标）；必须使用构建期生成的轻量索引。

### 12.2 缓存与部署

- 静态产物部署，带内容哈希的资源使用长缓存。
- HTML 使用短缓存 + 校验（沿用样本 C 的 `_headers` 思路）。
- 资源文件名带版本参数用于强制刷新（样本 C 的 `?v=20260906-1`）。
- 站点必须能完全离线镜像，不依赖外部 CDN（字体、图标、统计全部自托管或不用）。

### 12.3 素材与许可纪律

沿用本项目 Source Record 体系，并在站点上补齐样本 C 的 `ASSET-PROVENANCE.md` 做法：

- 品牌资产、字体、图标、案例产物、示例数据**逐项记录**来源、处理方式、许可、尺寸与哈希。
- 无法核验来源的素材**不补写来源，直接不用**。
- 第三方品牌标志仅作内容展示，并在页面说明归属。
- 案例中的个人数据、账号、联系方式必须移除后才能展示。
- 站点页面必须能显示**每个资产的权利状态**（至少对案例产物与图片生效）。

### 12.4 网站与 PDF 语义一致性

`check-parity.mjs` 至少检查：

- 同一章节在网站与 PDF 中的标题、概念定义、案例描述、验收标准文本一致。
- 网站独有的交互内容（trace、动态对比）在 PDF 中存在降级表达。
- PDF 中标注的 `evidence_cutoff` 与网站显示的证据截止日一致。

## 15. 未决问题

1. **品牌视觉最终确认**：§9 的"编辑型研究感 + 寿命三色"为建议方案，需要与系列名、系列主张一起定稿（阻塞于系列名未决项）。
2. **实时统计是否要**：本文档决定不显示访问量。若需要"社区活跃度"信号，可改用"贡献者数 / 案例提交数"等不与流量绑定的指标。
3. **案例产物托管位置**：站内 `public/cases/` 还是独立对象存储？涉及体积与许可，需要与实际产物体量一起决定。
4. **回放数据的标准化格式**：`trace.json` 的 schema 尚未定义，需要与卷 08 首章案例的 runner 输出对齐后冻结。
5. **搜索索引规模上限**：14 卷全文检索是否需要分片（按卷加载）尚需实测。
6. **是否提供离线包**：静态站点可打包为离线阅读包（对应 PDF 之外的第三种载体），成本与收益待评估。
7. **PDF 生成管线归属**：本文档只定义网站侧；`print/` 侧的构建器选型（Paged.js / PrinceXML / headless Chrome 等）另立文档。
