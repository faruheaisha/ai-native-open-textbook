## 一、Volume Contract

### 本卷承诺

学习者完成本卷后，能够从任务出发判断是否使用 Agent，解释 Agent 如何通过模型、工具、状态与环境反馈循环工作，选择合适的 workflow / agent pattern，构建或配置一个最小 Agent，读取运行轨迹，并用成功标准、停止条件、成本与失败测试评价它。

### 本卷不承诺

- 不把某个 Agent 框架写成标准答案。
- 不深讲 Claude Code、Codex、Qoder 等完整 Harness（归卷 09）。
- 不完整展开 Context Engineering、长期 Memory、Skills、MCP、Hooks（归卷 10）。
- 不把长期在线个人 Agent 的部署与人格系统塞入本卷（归卷 11）。
- 不替代卷 12 的系统安全、可靠性、红队和治理。
- 不把 Agentic RL、自我改进和 AI Scientist 当作已成熟常规工程（主要归卷 14）。

### 前置知识

卷 01（模型 / 产品 / 模式 / 界面与 Agent 的区别）、卷 02（LLM、Token、Context、推理与评测基础）、卷 03（API、Provider、成本、配额、数据边界）。

### 4.3 本轮新增的关键来源：microsoft/AI-Engineering-Coach

- **定位**：读本地 AI 会话日志 → 产出自评与改进建议（数据不出本机）。
- **可教学内容**：练习评分与周趋势；**45 条反模式规则**（提示质量 / 会话卫生 / 代码评审 / 工具掌握 / 上下文管理五类）；按语言 / 工作区 / 模型 / harness 的产出度量；**重复提示词 → 可复用 Skill 的发现**；agentic readiness 与 instruction-file 审计。
- **为什么重要**：本卷长期缺"**如何知道自己用得好不好**"这一层。这是目前唯一的机构级公开实践，且它把"卷 08 的使用 → 卷 10 的 Skill 沉淀"做成了产品功能。
- **使用边界**：45 条规则是**厂商观点**，非同行评审结论；引用须注明"微软提出的规则集"。教读者使用此类工具时，必须同时讲**会话日志里有什么**（提示词、代码片段、路径、可能的密钥）→ 卷 12。

## 八、开放问题与风险

1. **`Agent` 定义不统一**：各来源边界不同 → 保留 Source View，禁止用单一框架定义。
2. **框架偏见**：容易变成"某框架教程"。对策：同一最小行为在多框架实现（O08-08 已要求）。
3. **多 Agent 的过度宣传**：社区普遍高估其必要性 → 必须配反例（O08-07）。
4. **NC 决策依赖**：中文主线（Hello-Agents、Datawhale Agentic AI、zero2Agent 绿皮书）多为 NC，直接受 `04-待验证与决策队列.md` P1 决策影响。
5. **面试题的准确性**：`zero2Agent` 的 630 题来源未验证，**不得作为"真实考题"陈述**。
6. **论文与工程的落差**：论文复现成本高，须标注算力与成本前提。
