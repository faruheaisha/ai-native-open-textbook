# 网站与蓝皮书双载体出版范式

状态：`FROZEN PRODUCT MODEL v1.0`  
决策日期：2026-09-08  
适用范围：全 14 卷及后续案例、资源和动态更新

## 一、最终产品定义

本项目最终不是一个文档目录，也不是只部署一个课程网站。它是一套**同源、多出口、可持续更新的开放教材产品**：

```text
                    Canonical Content Corpus
                 结构化正文 / 证据 / 案例 / 资产
                              │
              ┌───────────────┼───────────────┐
              │               │               │
       Living Web         Bluebook PDF    Open Repository
       在线学习系统        版本化正式读本      研究与共创底座
       持续更新            稳定、可引用        可追溯、可复现
```

对外呈现为三个彼此配合的入口：

1. **网站**：读、搜、学、看演示、跑案例、查更新。
2. **PDF 蓝皮书**：系统阅读、收藏、打印、传播、正式引用。
3. **开放仓库**：查看来源、勘误、版本历史、案例资产和参与共创。

网站与 PDF 不是两套手工维护的内容。二者必须从同一份规范化内容源生成；任何只修改网站正文或只修改 PDF 正文的流程都视为架构缺陷。

全系列只建设一个统一网站。PDF 同时提供 14 本独立卷册、系列阅读指南和自动生成的全集合订本；独立卷是主要更新与引用单位，合集是完整学习与收藏入口。制作顺序见 `06-全系列制作与集成路线.md`。

## 二、两种载体的职责边界

| 内容 | 网站 | PDF 蓝皮书 | 原因 |
|---|---|---|---|
| Stable Core | 完整 | 完整 | 构成教材长期骨架 |
| Current Practice | 最新状态 | 截止出版日的精选快照 | 产品与流程持续变化 |
| Frontier Snapshot | 日期化专题、持续更新 | 可选年度/版本附录 | 不污染稳定正文 |
| 产品版本、价格、入口 | 动态卡片 | 原则上只给核验日期与网站二维码 | 避免 PDF 快速失效 |
| Source Views 与关键引用 | 可展开查看 | 精选呈现 | 网站适合展示证据层级 |
| 完整 Source Record | 链接或证据面板 | 不全文收录 | 保持阅读流畅 |
| 案例过程 | Trace、视频、GIF、可下载资产 | 关键步骤、截图、结果摘要 | 动态媒体无法进入纸面 |
| 练习与评测 | 可交互、可提交、可更新 | 离线题目、评分标准、答案入口 | 两种学习场景不同 |
| 勘误与 Changelog | 实时 | 指向版本勘误页 | PDF 是不可变快照 |

一句话概括：

> **网站是活的课程系统；蓝皮书是某个证据截止日的稳定知识快照。**

## 三、对标吸收与超越

### 豆包工作指南：吸收在线课程产品能力

截至 2026-09-08，`DoubaoWorkGuide` 官方仓库说明其在线版提供独立章节、全文搜索、章节导航、场景任务速达、图片/视频、明暗主题和移动端适配，并将内容数据、媒体资源与界面逻辑分层维护。

本项目吸收：

- 在线阅读优先于在 GitHub 连续阅读。
- 新手顺序阅读与“我有一个具体任务”的场景速达并存。
- 左侧课程树、正文、页内目录、前后篇导航和全文搜索。
- 图片、视频、流程图、案例成果在页面内完成教学，不作为装饰。
- 移动端可读、明暗主题、本地阅读进度。
- 内容层与展示层分离。

本项目不直接照搬：

- 14 卷规模不采用一个超大 JSON 保存所有正文；正文以每章独立 Markdown/MDX 为真源，构建期生成索引。
- 不让产品分类直接决定知识结构。
- 不把所有公开案例自动提升为教材案例；仍使用 EVL 证据等级。
- 在普通文档站能力之上增加来源、核验日期、稳定性和许可状态。

参考：[DoubaoWorkGuide 官方仓库](https://github.com/AlephAITech/DoubaoWorkGuide)、[在线站点](https://doubaowork.homes/)。

### 花叔橙皮书：吸收系列出版物能力

截至 2026-09-08，花叔的橙皮书系列主页以统一系列品牌呈现卷号、标题、副标题、页数、发布状态和 PDF 下载；单卷页面用简短卷首说明与清晰目录建立阅读预期。部分书还提供 GitHub、HTML/EPUB 或配套产物。

本项目吸收：

- 一本一主题、一卷一承诺，而不是把所有内容塞进“大全”。
- 统一系列封面、卷号、标题、副标题和视觉识别。
- 首页直接展示已发布、编写中、版本和下载入口。
- 单卷页明确适合谁、学完能做什么、目录和预计阅读成本。
- PDF 不是网页打印稿，而是经过专门排版的正式读本。
- 真实实践、失败经验、命令速查和附录共同构成一本可用的手册。

本项目需要加强：

- 每个动态事实显示 `last_verified` 与适用版本。
- 区分官方事实、来源观点、作者经验、编辑综合和未验证线索。
- PDF 带证据截止日、源代码版本、勘误入口和永久链接。
- 案例按 EVL 标记，避免“作者跑通过一次”被误解为普遍效果。
- 第三方正文、代码和媒体分别记录许可，不以“免费”替代权利核验。

参考：[橙皮书系列主页](https://www.huasheng.ai/orange-books/)、[Codex 橙皮书单卷页](https://www.huasheng.ai/orange-books/codex/)。

## 四、网站信息架构

### 一级导航

```text
Start       从哪里开始
Roadmap     按能力与角色选路线
Volumes     14 卷教材
Labs        可复现案例与练习
Explore     概念、任务、产品与实现地图
Resources   来源课程、论文、官方文档与资产
Updates     更新、勘误与 Frontier Snapshot
About       项目、作者、许可证与贡献
```

### 首页

首页在一个屏幕内回答五个问题：

1. 这是什么：AI 原生开放教材与蓝皮书系列。
2. 为谁而写：普通用户、知识工作者、Builder、Agent/LLM 工程师。
3. 能获得什么：认识 → 选择 → 使用 → 组合 → 验证 → 构建 → 研究。
4. 从哪里开始：角色入口、推荐卷和第一个可完成任务。
5. 为什么可信：来源、证据等级、核验日期、开放勘误与可复现案例。

首页主要区块：

- Hero：项目名、价值承诺、开始学习、下载最新蓝皮书。
- Role Tracks：五种学习出口。
- 14 Volumes：卷册封面墙，显示状态、适合人群和预计投入。
- Start with a Task：按真实任务进入课程。
- Featured Labs：已复现案例和最终 artifact。
- Current Updates：动态事实与新版本，不混入稳定正文。
- Source Curriculum：Datawhale、Hugging Face、Microsoft 等源课程关系。
- Open Contribution：勘误、案例提交、来源推荐。

### 系列页与单卷页

系列页借鉴出版物陈列逻辑：

- `Published / In Research / Writing / Updating` 状态。
- 卷号、封面、标题、副标题、版次、页数、最后更新。
- 在线阅读、下载 PDF、查看来源/仓库三个入口。

单卷 Landing Page 包含：

- 卷册承诺与非目标。
- 适合人群与前置知识。
- 学习结果与毕业产物。
- 章节目录与完成进度。
- Canonical Cases。
- 当前 PDF 版次与历史版本。
- 勘误、贡献者和引用方式。

### 章节阅读页

桌面端采用三栏：

```text
┌──────────────────┬────────────────────────────┬──────────────────┐
│ 卷册 / 章节树     │ 正文与案例                  │ 页内目录 / 证据   │
│ 学习路径          │ 学习目标、概念、练习、产物   │ 来源、核验、下载   │
└──────────────────┴────────────────────────────┴──────────────────┘
```

移动端收为单栏，目录和证据进入可打开面板。

每章页头固定展示：

- 所属卷、章节号、预计时间。
- `Stable / Current / Frontier` 内容标签。
- `last_verified`、适用版本和章节状态。
- 在线阅读进度、下载本章、打开 PDF 对应卷。

章节正文支持：

- `ConceptBlock`：稳定概念。
- `SourceView`：机构/课程观点，不假装统一。
- `ComparisonTabs`：同一任务的不同实现。
- `CaseReplay`：按步骤播放输入、工具调用、观察、失败和结果。
- `ArtifactPreview`：文档、表格、PPT、代码、图片、视频等成果。
- `EvidenceBadge`：EVL 与综合等级。
- `FreshnessBadge`：最后核验与更新期限。
- `SafetyBox`：权限、隐私、成本和不可逆动作。
- `TryIt`：无代码练习、代码实验或下载模板。

## 五、PDF 蓝皮书产品规范

### 系列命名

建议对外母品牌暂用：

> **AI Native Bluebooks / AI 原生蓝皮书系列**

这是工作名，正式品牌仍进入决策队列。颜色不是装饰：蓝色代表证据、工程可信度和可复查；每卷可有辅助色，但保留统一的蓝色主识别。

### 每卷封面必须包含

- `VOL. 01–14`。
- 中英文标题与一句副标题。
- 系列名与项目标识。
- 版次，例如 `Edition 2026.1 / v1.0.0`。
- 证据截止日 `Evidence cutoff`。
- 适用版本范围（仅在产品型卷册需要）。
- 作者、编辑与贡献者角色。
- 官网短链接或二维码。

### 固定前置页

1. 扉页与版权/许可。
2. 本卷定位：解决什么、不解决什么。
3. 适合谁、前置知识和阅读路径。
4. 学习结果与毕业产物。
5. 如何识别 `Stable / Current / Frontier`、`Source View` 与 EVL。
6. 版本、证据截止日、引用方式与在线勘误入口。
7. 目录。

### 单章版式骨架

```text
Opening Question / 真实问题
→ Learning Outcome / 学完能做什么
→ Mental Model / 一张核心图
→ Canonical Source Views / 来源如何定义
→ Explanation / 教材综合正文
→ Canonical Case / 典型案例
→ Hands-on / 可跟做任务
→ Artifact / 可检查产物
→ Failure & Safety / 失败、边界与风险
→ Evaluation / 自测与验收
→ Further Sources / 原始资料与在线更新
```

不同章节可以采用概念型、实战型或深度分析型节奏，但不得删除学习结果、证据、失败和验收四类信息。

### 固定后置页

- 本卷概念表与缩写。
- 案例/Artifact 索引。
- 来源与参考文献。
- 第三方素材与许可证清单。
- 版本历史和已知限制。
- 网站、勘误、贡献与下一卷入口。

### 版式原则

- A4 作为主印刷尺寸，同时验证平板阅读。
- 中文正文优先保证长时间阅读，不追求过密信息墙。
- 统一页眉、页脚、卷号、章节号、页码和版本。
- 表格可读宽度优先；超宽对比转为分组卡片或横向附录。
- 代码、命令、Prompt、输入和输出使用不同但克制的视觉语义。
- 二维码只连接持久网址，不连接可能失效的临时下载地址。
- PDF 必须嵌入字体、保留可复制文本、书签和可点击链接，并通过屏幕与打印渲染检查。

不冻结每卷页数。建议以学习闭环决定长度；页数只作为读者预期，不作为质量目标。

- 可运行实验 → 输入/输出样例 + 环境说明 + 仓库路径。

## 七、发布与版本机制

### 网站

- `main` 对应已审核在线内容。
- 动态事实可以独立更新，不必重发整本 PDF。
- 页面显示内容更新时间、事实核验时间和适用版本；三者不能混为一个日期。
- 更新日志按 `Correction / Evidence Update / Product Change / New Case / Editorial Change` 分类。

### PDF

- PDF 是不可变发行版；同一文件发布后不静默替换。
- 每次发布记录 `edition`、`source_commit`、`evidence_cutoff`、构建时间和文件校验值。
- 小勘误进入在线 Errata；实质修改发布新 patch/minor 版。
- 历史版保留并标注 superseded，不让旧链接悄悄指向不同内容。

建议版本方式：

```text
Edition 2026.1 · v1.0.0
2026 = 年度知识环境
.1   = 当年第几个正式版次
v1.0.0 = 内容语义版本
```

### 发布门禁

网站章节进入 `published` 前必须：

- Chapter Evidence Packet 完成。
- 关键主张可追溯，分歧未被抹平。
- 案例达到该章节要求的 EVL，并标清复现债务。
- 许可与第三方资产清单通过。
- 链接、移动端、可访问性和搜索索引检查通过。

PDF 卷册发布还必须：

- 冻结证据截止日与源代码提交。
- 自动生成目录、书签、页码、引用和第三方清单。
- 全量渲染为图片进行视觉 QA。
- 检查字体、表格、代码、链接、二维码、孤行和空白页。
- 抽查网站与 PDF 同一章节的语义一致性。

## 八、课程不是“书的电子版”

网站的核心优势不是更新快，而是能表达纸面不能表达的学习行为：

- 从角色、任务、概念和产品实现四个入口进入同一知识图谱。
- 在同一任务中切换 Claude、Codex、Qoder、Qwen、开源框架等实现。
- 回放 Agent trace，观察模型决策、工具调用、失败与人工介入。
- 直接下载 Task Spec、Prompt、Skill、Workflow、Notebook 与最终 Artifact。
- 显示来源、证据等级、最后核验和已知限制。
- 收集勘误与案例复现结果，让课程随证据演进。

PDF 的核心优势也不是“离线”：它迫使项目在一个证据截止点做出编辑判断，形成有开头、有路径、有结论、有边界的完整读本。

因此，最终范式应概括为：

> **以网站承载活知识、以蓝皮书沉淀稳定判断、以开放仓库保存证据与共创过程。**
