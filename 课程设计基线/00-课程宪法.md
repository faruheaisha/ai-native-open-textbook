# 课程宪法

## 项目定义

本项目不是 AI 工具大全，也不是产品使用手册集合。它是一套面向中国大学生、AI 原生知识工作者、独立开发者和 Agent/LLM 工程师的开放教材与可信资源系统。

最终能力链是：

```text
认识 → 选择 → 使用 → 组合 → 验证 → 构建 → 研究
```

## 18 条底层原则

1. **Concept first, product second.** 知识先于产品。
2. **Task first, tool second.** 任务先于工具。
3. **Evidence first, writing second.** 先取证，再写作。
4. **Canonical source first.** 原始论文、标准、官方文档和官方代码优先。
5. **One fact, one source of truth.** 同一事实只维护一个权威节点。
6. **Verify at a point in time.** 动态事实必须带验证日期。
7. **Reuse excellence before rebuilding it.** 优先吸收已有优秀成果。
8. **Reproduction upgrades confidence; it is not always required.** 复现用于提高证据等级，不是所有内容发布的前置条件。
9. **Teach failure, not only success.** 课程必须解释失败模式和边界。
10. **Complexity is opt-in.** 复杂性由学习者主动选择。
11. **Every learner deserves a complete no-code path.** 永远不写代码的学习者也拥有完整、有价值的毕业路径。
12. **Progressive disclosure.** 同一概念按使用者、开发者、工程师逐层展开。
13. **Do not collect everything.** 不以数量、Stars 或热度代替教学价值。
14. **Always keep discovering.** 持续扩展来源，避免信息茧房。
15. **Public does not automatically mean reusable.** 公开可读不等于可复制、改编或重新发布。
16. **A course is finished only when the learner can do something.** 学习结果必须可观察、可验收。
17. **One corpus, multiple publications.** 网站与 PDF 必须由同一内容真源生成，不分别手工维护正文。
18. **Living web, editioned book.** 网站承载持续更新与交互，蓝皮书承载有证据截止日的稳定版本。

## 最终出版形态

项目以三种互补载体公开：

- 网站：在线学习、搜索、交互案例、动态事实、更新与勘误。
- PDF 蓝皮书：系统阅读、打印传播、正式引用和版本化知识快照。
- 开放仓库：来源、证据、案例资产、版本历史与社区共创。

网站与 PDF 不是主从关系，也不是彼此复制。二者从同一 Canonical Content Corpus 生成，各自表达最适合该介质的学习体验。详细规则见 `05-网站与蓝皮书双载体出版范式.md`。

## 两条平行主干

知识侧：

```text
Papers / Standards / Official Docs / Open Courses / Engineering Sources
                              ↓
                           Evidence
                              ↓
                      Textbook Synthesis
```

实践侧：

```text
Canonical Product / OSS Implementation / Real Case / Workflow / Skill / Artifact
                                   ↓
                                Hands-on
```

两侧只在章节中汇合，不允许用产品目录代替知识结构。

## 教材写作立场

- 以知识为中心、以第三人称写作，不把教材写成产品 onboarding。
- 正式标题优先沿用成熟课程、官方文档和工程社区已经稳定使用的术语。
- 区分 `Source Definition`、`Source View`、`Editorial Synthesis`、`Proposed Model`。
- 对分歧与歧义进行展示、比较和解释，不偷偷消除。
- 不因“原创”要求而把准确的概念改写到失真；是否可以原文复用由许可证决定。

## 产品进入教材的四级制度

1. `Canonical Exemplar`：深讲，用于解释一个关键范式。
2. `Comparative Implementation`：只讲与主案例不同的实现选择。
3. `Ecosystem Reference`：用于建立生态地图。
4. `Frontier Radar`：只在动态网站中持续观察。

新产品出现不等于新增章节。只有当它揭示了现有典型案例无法解释的新知识时，才有资格升级。

## 多出口学习观

普通用户路线不是开发者路线的低级版。课程允许多个正式出口：

- AI Native User
- AI Native Knowledge Worker
- AI Builder / Vibe Coder
- Agent Developer
- Agent Engineer
- LLM Engineer / Researcher
