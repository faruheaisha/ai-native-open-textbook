状态：`FROZEN PRODUCTION ORDER v1.0`

## 一、总交付目标

项目的完成条件不是“写出几本重点卷”，而是同时完成：

1. 14 卷课程全部达到可发布标准。
2. 每卷拥有独立 PDF 蓝皮书和完整在线版。
3. 14 卷进入同一个网站、同一个设计系统、同一个搜索与知识索引。
4. 生成蓝皮书合集：系列目录、14 本独立 PDF、全集合订本和资产清单。
5. 概念、术语、来源、案例、产品事实和引用在全系列范围内去重并可追溯。

## 二、必须区分三个顺序

### 阅读顺序

读者始终看到卷 01 → 卷 14 的课程结构。它表达知识依赖，不因制作先后而改变。

### 制作顺序

先做最能验证课程方法的卷：

```text
卷 08 Agent
→ 卷 04 办公与个人知识系统
→ 卷 01–03 基础层
→ 卷 05–07 应用层
→ 卷 09–11 Agent 工程层
→ 卷 12–14 可靠性、部署与前沿层
→ 全系列整合发行
```

### 发布顺序

单卷通过门禁后可以先行发布，网站显示全系列状态；但只有 14 卷全部通过跨卷集成，才能发布“蓝皮书全集”。

制作顺序不等于重要性排序，也不改动最终卷号。

## 三、为什么先做卷 08，再做卷 04

### 第一标杆卷：卷 08 AI Agents & Agentic Workflows

卷 08 用于验证这套教材最难的技术方法：

- 多个高质量来源定义不一致时如何写教材。
- Agent、Workflow、Tool、Loop、Planning、Multi-Agent 等术语如何分层。
- 理论、框架、真实任务、运行轨迹、失败和评测如何形成闭环。
- 同一知识怎样同时服务普通用户、Builder 和 Agent Developer。
- 网页中的 Case Replay 如何降级为 PDF 中的状态图与轨迹表。

卷 08 完成后，项目应拥有第一个真正可复用的技术卷模板。

### 第二标杆卷：卷 04 AI Knowledge Work & Personal Knowledge Systems

卷 04 用于验证另一半课程能力：

- 不写代码的学习者是否能获得完整而非缩水的毕业路径。
- Word、Excel、PPT、PDF、文件、会议、邮件、调研等办公任务能否用统一任务链解释。
- Work Agent、Chat 产品、知识库和传统办公软件如何比较而不写成厂商手册。
- Obsidian、Notion、NotebookLM、Zotero 等不同知识系统如何回到稳定原则。
- 一次性 AI 对话如何沉淀为可维护、可检索、可复用的个人知识系统。

卷 04 完成后，技术深度和大众可用性两种标杆都成立，其余卷才能安全规模化。

## 五、卷 08 完整制作候选结构

以下是研究队列，不是未经取证就冻结的最终目录：

### Part I：认识 Agent

1. AI 智能体导论：定义、边界与控制权。
2. 模型、目标、环境、状态、工具与反馈。
3. Workflow、Automation 与 Agent 的选择。

### Part II：理解 Agent 循环与模式

4. Tool Use 与 Agent Loop。
5. ReAct、Planning、Reflection 与 Evaluator。
6. Routing、Chaining、Parallelization 与 Orchestrator–Workers。
7. 单 Agent、多 Agent 与人在回路。

### Part III：从任务到实现

8. 写出可执行的 Agent Task Specification。
9. 无代码/低代码 Agent Workflow。
10. 框架如何实现同一知识骨架。
11. 真实任务 Case：Research、Document、Coding、Automation。

### Part IV：验证与进入工程层

12. Agent Evaluation、Failure 与 Cost。
13. 权限、停止、恢复与最小安全模型。
14. 从 Agent 原型进入 Harness、Context、Memory 和 Production。

首章已完成 C2 Evidence Packet；其余章节必须逐章建证据包后才能定名。

## 六、卷 04 完整制作候选结构

卷 04 必须同时覆盖“AI 办公”和“个人知识库/个人知识系统”，不能拆成零散工具技巧。

### Part I：AI 知识工作的共同骨架

1. 从 Prompt 转向 Task Specification 与 Artifact。
2. Workspace、Context、Files、Data 与 Verification。
3. Work Agent、Chat、Office Copilot 与传统自动化的边界。

### Part II：真实办公任务

4. 文档：读取、整理、写作、审阅和版本交付。
5. 表格与数据：清理、分析、可视化和结论验证。
6. PPT：信息结构、视觉表达、生成和人工审阅。
7. PDF、扫描件、图片和混合文件处理。
8. 文件夹整理、批量任务和桌面工作空间。
9. 会议、邮件、待办、简报与团队协作。
10. 调研、信息综合与带引用的知识产物。

### Part III：个人知识库与个人知识系统

11. 个人知识系统解决什么问题。
12. Capture：输入、收件箱、来源与去重。
13. Organize & Connect：目录、标签、属性、链接与项目。
14. Retrieve & Synthesize：检索、问答、对照、写作与决策。
15. Obsidian、Notion、NotebookLM、Zotero 的结构差异。
16. 建立 Agent-readable Workspace：让 AI 能安全读懂你的知识环境。
17. 知识维护：过期、冲突、归档、隐私、备份与迁移。

### Part IV：把一次成功变成工作系统

18. Prompt、Template、Skill、Workflow 与 Automation。
19. Canonical Case：从散乱资料到可持续个人知识系统。
20. 个人工作系统的验收、迭代与边界。

卷 04 的最终章数可以合并，但办公任务链、PKM 生命周期和综合案例三者不得缺失。

## 七、每卷 Definition of Done

### A. 知识完成

- 卷册职责、前置知识和非目标清楚。
- 所有正式章节完成 Chapter Evidence Packet。
- Canonical Concepts 有唯一首讲位置，后续卷只递进或引用。
- Source View、编辑综合和动态事实没有混淆。

### B. 学习完成

- 每章有 Learning Outcome 和 Evidence of Learning。
- 每卷同时提供与目标读者匹配的完整学习路径。
- 至少一个贯穿卷册的 Canonical Case。
- 练习要求产出可检查 Artifact，而非只做记忆问答。

### C. 证据与资产完成

- 来源、主张、版本、许可和核验日期可追溯。
- 核心案例达到预设 EVL；未完成复现的债务公开。
- 图片、视频、代码、数据和第三方附件逐项核权。
- 动态产品事实进入 Live Facts，不散落在多个章节。

### D. 双载体完成

- 同一内容源成功生成网站章节与 PDF。
- 网站搜索、导航、移动端、媒体和证据面板通过检查。
- PDF 封面、目录、书签、页码、字体、链接和引用通过视觉 QA。
- 网站与 PDF 的稳定正文语义一致。
- 单卷 Release Manifest、Changelog、Errata 和历史版本入口齐全。

只完成 Markdown 正文不算完成一卷。

### 14 本独立 PDF

适合下载单卷、独立更新、轻量阅读和明确引用。它们是主要发行单位。

### 系列阅读指南

介绍 14 卷关系、角色路线、学习顺序、概念地图、版本与引用方式。

### 全集合订本

由 14 本独立内容自动生成，不单独手工维护正文。它提供全局目录、统一页码、全局概念索引、案例索引与参考文献索引。由于文件较大，它是合集入口而非唯一下载方式。

### 发行清单

`MANIFEST.json` 记录每卷版次、source commit、evidence cutoff、文件哈希、许可证和 superseded 状态，保证合集可验证。

## 十、跨卷集成规则

- 每个 Canonical Concept 指定一卷首讲，例如 Agent 在卷 08 首讲，Harness 在卷 09 首讲，Memory 深讲在卷 10。
- Product 不是跨卷复制的正文，而是中心化 Implementation/Live Fact 节点。
- 同一案例跨卷复用时改变学习任务，不复制整段过程。
- 所有术语进入全局 Glossary，但每卷保留必要局部词表。
- 每完成一卷，反向检查已经完成的卷；新证据允许产生带记录的修订。
- 全集发布前执行重复内容、矛盾主张、失效链接、许可、版本、交叉引用和视觉一致性审计。
